  # 岩谱 · LithoSpectra

  **地质样本库** — 单文件样本库 · 图层化画布 · 样本标注 · 光谱曲线
</div>

名字取"谱"字的三重含义：**光谱**（高光谱岩性识别）、**图谱**（样本库本身）、
**谱系**（多级分类树）。

图标画的是一次分类。暖象牙底板上并排两块：左边六枚方形像元，色调杂乱不纯，
是遥感影像本来的样子；右边一根平顶圆底的柱体，钻孔柱状图的轮廓，内部三层连续
干净，是判读之后的岩性层序。离散对连续，杂乱对归类，中间那道空白就是模型做的事。

两侧严格按行对齐。左块第二行有一枚陶土色像元，右块第二层整层是同一个陶土色——
从混杂像元里检出一个信号，整层被判为该类。全图只有这一点色相。

兼容三种既有的样本组织方式，类别支持任意层数分级，导出始终遵循
「一个矢量文件代表一类样本」。

## 1. 运行

程序以打包好的 `.app` 运行，不提供 Python 启动脚本：

```bash
conda env create -f environment.yml
conda activate samplelib
bash packaging/build_web_macos.sh     # 编译页面、打包、自检，产物 packaging/dist-web/LithoSpectraWeb.app
```

界面是 React 写的页面，装在系统自带的 WebView 窗口里（macOS 为 WebKit，Windows 为
Edge WebView2），是一个独立的桌面程序，不需要浏览器、不联网也能用。整个程序只有
**一个窗口**，浏览与标注是它的两种模式。

| 层 | 位置 | 技术 |
| --- | --- | --- |
| 界面 | `web/src/` | React + TypeScript + Ant Design，地图 OpenLayers |
| 接口 | `webapi/` | FastAPI，跑在本进程内的 127.0.0.1 随机端口 |
| 内核 | `samplelib/` | 样本库存储、会话、导入导出、图层渲染、功能模块的计算部分 |
| 窗口 | `webapi/desktop_app.py` | pywebview，负责原生窗口、菜单栏、文件对话框与拖入文件；打包入口 `packaging/entry_web.py` |

`webapi/desktop_app.py` 顶部的配置区可设置启动时打开的样本库、是否恢复上次打开的
样本库，以及页面来源（打包好的页面或前端开发服务器）。

改样本几何、删样本、删类别先进暂存区，点「保存」才写库；新建类别、改名、改色、
拖动调整层级直接落库。两类操作共用一个撤销按钮，按发生顺序回退。底图瓦片由接口层
代取并写进 `data/tilecache`，密钥不进页面。

勾选逐条样本记在会话里，是导出的工作集。导入（目录 / 根目录 / 单个矢量 / 按属性）、
导出（含树上的导出层级标记与点要素缓冲）、新建 / 关闭 / 另存为 / 备份到 / 从备份
还原，调用的都是 `samplelib` 里的函数。这些长任务在后台线程里独占样本库运行，界面
显示进度并可取消，见 `webapi/tasks.py`。「最近打开」记在 `state/session.json`。

画布的鼠标约定：中键在任何工具下拖动平移；左键拖动平移只属于「平移」「取谱」两件
工具，其余工具下左键各有用处（框选、落点、拖顶点）；鼠标在画布上时按住空格，左键
临时变平移，适合没有中键的触控板。按下到松开抖动 6 像素以内仍算单击；正在画面时
右键是闭合。图层面板里双击一个图层缩放到它的范围（「样本库 · 样本」缩放到全部样本），
点中参考图层后按 Tab 切换它的显示。

影像与配准图片按视窗向接口层要图（WMS），每个图层只画最新的那一张，平移、缩放
快时排在后面的旧请求直接放弃。长边超过 3000 像素（PNG / JPG 超过 2000 像素）、又
没有现成金字塔的图，加载后在后台把当前显示的波段另存成分块、带金字塔的 GeoTIFF
（图层清单里显示「准备中」），之后缩放读金字塔、放大按块读，原文件不动。这些显示
用的副本放在 `data/rastercache`，换显示波段另建一份，总量超过 8 GB 时删最久没用的。

前端开发时把 `webapi/desktop_app.py` 配置区的 `UI_SOURCE` 改为 `dev`，另开终端在
`web/` 下运行 `npm run dev`，改代码即时刷新。

拖文件进窗口时不用 pywebview 的 DOM 事件监听：那条路会把事件对象连同整棵 DOM
树序列化后传给 Python，拖动途中每次 dragover 都在界面线程上做一遍，界面越复杂
卡得越久。现在由页面自己接 drop，只把文件名交给外壳的 `dropped_paths` 换成真实
路径。栅格出图或建显示金字塔时，画布顶上显示进度条。

打包成独立程序见第 15 节。

## 2. 存储格式

一个样本库 = 一个 `.gpkg` 文件（GeoPackage，本质是 SQLite），可被 QGIS、
ArcGIS 直接打开。内部结构：

| 图层 / 表 | 作用 |
| --- | --- |
| `samples_point` | 点样本，EPSG:4326 |
| `samples_polygon` | 面样本，EPSG:4326，统一存为 MultiPolygon |
| `sl_class` | 类别表，表的 FID 即 `class_id`，`parent_id` 表达任意层数的类别层级 |
| `sl_meta` | 库名、版本、创建日期等元数据 |

样本字段：`class_id`、`label`（自定义名称）、`source`（原始文件名）、
`native_crs`（导入前坐标系）、`created`、`attrs`（原始属性的 JSON 备份）。
类别字段除名称、类别号、工区、颜色、说明外，还有 `attrs` 记录该类的分类
键值对（如 `{"岩性大": "火山岩", "代号": "T3bb2"}`），以及 `origin` 记录导入时的
原始名称、类别号、工区与上级——后者只在建类时写入一次，是"恢复初始状态"的依据。

所有几何统一投影到 EPSG:4326 入库，导出时可还原回 `native_crs` 或指定坐标系。
打开旧版本样本库时会自动补齐后加的字段，不需要重建。`sl_meta` 里的 `format_version`
是格式版本：次版本只加字段，老库打开即升级并把版本号写回去；主版本变了意味着表
结构或字段含义变了，比程序支持的更新的库会拒绝打开（只读也拒绝——按老格式去读
新库，读出来的也不可信）。需要改数据的升级步骤登记在 `SampleStore.MIGRATIONS`
里，按版本号顺序各跑一次，每步一个事务。

## 3. 三种样本格式的导入

| 格式 | 类别载体 | 导入入口 |
| --- | --- | --- |
| A 一个目录一个工区，一个文件一类样本 | 文件名 | 导入 → 导入旧样本目录 / 样本库根目录 |
| B 单个文件整体作为一类 | 文件本身 | 导入 → 导入单个矢量文件 |
| C 单个文件装多类样本 | 属性字段 | 导入 → 按属性导入 |

### 格式 A / B：文件名承载类别

命名解析兼容历史上的多种写法：

| 文件名 | 解析结果 |
| --- | --- |
| `Label_0_unknown_20260404.shp` | 类别号 `0`，类别名 `unknown`，日期 `20260404` |
| `label_10_鄂拉山花岗闪长岩reproj.shp` | 类别号 `10`，类别名 `鄂拉山花岗闪长岩` |
| `Label_1__第四纪reproj.shp` | 类别号 `1`，类别名 `第四纪` |
| 无法解析的名称 | 类别号留空，文件名作为类别名 |

目录下若存在 `description.json`，其中的 `label_name`、`sample_type`、
`description` 会覆盖从文件名解析出的结果。

**导进一个已有类别的工区时，新的一批永远是新类别，谁也不并进谁**（格式 A / B
共用一条链路）：

* 工区里已有同名的类别（不管在哪一层、是分组还是基础类别）→ 这次导入的叫
  「泥岩1」；「泥岩1」也有了叫「泥岩2」，依此类推，导入报告里会说一声。序号不
  叠加：复制「泥岩2」得到的是「泥岩3」而不是「泥岩21」——名字尾巴上的数字若是
  早先加的序号（去掉之后的「泥岩」就在工区里），从「泥岩」接着数；「T3bb2」这种
  本来就带数字的代号，「T3bb」不存在，照旧按整个名字加。点面混合文件拆出的
  「名（点）」「名（面）」同样查重。重复导同一个文件也是这样：两批样本各占一个
  类别，要合请自己拖。文件名前缀那个号不参与
  判断——它只是树的排序键。早先只要号对上就算同一类，往一个已有「1 沉积岩」的
  工区里导 `1_泥岩.shp`，泥岩的样本会被一声不响地并进沉积岩下面随便一片叶子：
  树上没长出新类别、工区的总数却涨了，样本落在了错的类别里。
* 一个文件里点面都有 → 建分组 + 「名（点）」「名（面）」两个基础类别，与从前一样。

「按属性导入」的骨架靠"同一位置、同一组分类键值对"认（见格式 C）：**分组**复用，
同一份岩性图导两次树不会长两棵；持有样本的**末级类别**不复用，同一父级下已有
「砂岩」就另建「砂岩1」——不同分支各自有一个「砂岩」是分类字段本来的样子，
不算重名。

```python
from samplelib import SampleStore, io_shp

store = SampleStore.create("地质样本库.gpkg", name="地质样本库", overwrite=True)
io_shp.import_library_root(store, "SampleLibrary")        # 多工区一次导入
io_shp.import_vector_dir(store, "SampleLibrary/青海都兰")   # 单工区导入
```

### 格式 C：属性字段承载类别

一个矢量文件装下全部样本，靠属性字段区分类别，且字段之间常有天然层级。
导入时指定分级字段，字段组合的每个唯一取值成为一类；**分级字段可以指定
任意多个**，例如 `岩性大 → 纪 → 群 → 岩性` 会建出四级类别树：

```
沉积岩
└── 青白纪-长城纪
    └── 万宝沟群
        ├── 白云岩…
        └── 碳酸盐岩…
```

```python
from samplelib import io_attr

# 先看看有哪些字段可用
profiles, info = io_attr.profile_fields("SampleForShen.shp")
io_attr.suggest_class_fields(profiles)        # -> ['岩性大', '代号']

io_attr.import_by_attribute(
    store, "SampleForShen.shp",
    class_fields=("岩性大", "纪", "群", "岩性"),   # 任意多级
    region="海德乌拉", collapse_empty_levels=True,
    description_fields=("组", "代号"))
```

界面上的「按属性导入」对话框会列出每个字段的填充率、唯一值数与示例，
点击「分级」列即可设定层级，并实时预览会生成多少类别。

**中间层字段为空时自动折叠。** 地层字段往往只在部分要素上有值（海德乌拉数据
里"群"只有 16% 的要素填写）。若照直建树，41 个末级类别里会有 36 个的路径带
「未分类」占位节点。折叠后有"群"的分支保持四级、没有的自然收成三级，因此
**同一个库里不同分支的层数可以不同**——导出对此有专门处理，见下一节。

三点约定：

* **类名字段在同一类内有多个取值时不会以偏概全。** 例如八宝山组第二段
  （`T3bb2`）同时含安山岩、玄武岩、流纹岩，此时类别用分级字段的取值命名，
  并把全部岩性写入类别说明。
* **同一末级取值出现在不同上级分类下会分别建类并告警**，用于暴露源数据里
  分类字段前后不一致的情况。
* **空几何要素会被跳过**并计入导入报告。
* **同一工区里已有"同一位置、同一组分类键值对"的类别时复用它**，样本追加到原类别下，
  不再长出第二棵一模一样的树；换一个工区导同一份文件仍会各建各的。整个建树写库
  过程是一个事务，中途失败整批回滚，不留半棵树。

## 4. 导出

**导出结构只有一种：一个矢量文件代表一类样本。** 可选择的是"一类"按哪一层算：

| 导出层级 | 含义 |
| --- | --- |
| 末级类别（默认） | 每个直接持有样本的类别一个文件 |
| 第 N 层 | 按第 N 层类别聚合，N 按样本库实际最大深度动态给出 |
| 树中已勾选的类别 | 由勾选状态推断导出单元，可按分支单独指定层级，见下 |

**对话框顶上那一行实时告诉你这次会得到什么。** 「导出样本」与「裁剪样本块」
的顶行写着"当前勾选 N 条样本，涉及 M 个类别 → 按此层级将导出 K 个类别、F 个
文件，共 S 条样本"（裁剪写的是"裁出 K 个标签"），换一个层级、勾/取消「只裁当前
勾选的样本」它就跟着改。数字由 `LibrarySession.export_preview` 算，走的是导出
时同一个 `io_shp.export_targets`——预告和结果对不上比没有预告更糟。一个单元里
点面都有时按两个文件数，与导出一致；层数不足、不在任何单元之下这类兜底说明写
在下面的提示行里。

**层数不齐时不会丢样本。** 按第 N 层导出时，若某个分支的深度不足 N（例如
旧格式导入的扁平类别只有 1 层），该分支退回按自身的末级类别导出，并在报告中
列出这些分支。导出结束会做覆盖校验，报告"应导出 N 条 / 实际导出 N 条"。

以一个含三种格式、最大 4 层、共 4103 条样本的库为例：

| level | 文件数 | 样本数 |
| --- | --- | --- |
| leaf | 81 | 4103 |
| 1 | 45 | 4103 |
| 2 | 57 | 4103 |
| 3 | 80 | 4103 |
| 4 | 81 | 4103 |

**按勾选导出**时，整支勾选的类别合并成一个文件，只勾了小类就各自成文件。
每条被选样本恰好归到它所属链上**最深**的那个单元，同一条样本绝不会出现在两个
文件里。分组不存样本、基础类别不挂子类别，所以单元之间通常互不为祖先后代；
万一库里仍有"自己直接持有样本、子类别又各自成单元"的父节点（存储层不拦），父
节点自身那份也自成一个单元，不会因为"不在任何单元之下"被跳过。

**同一次导出里，不同分支可以按不同层级拆分。** 勾选状态只能表达"要哪些样本"，
表达不了"这一支按哪一层拆文件"，而常见诉求恰恰是一支合并、另一支拆开：

```
沉积岩  ☑  11 个子类   → 想整支导成 1 个文件
第四系  ☑   2 个子类   → 想让洪冲积、冲积各自 1 个文件
```

在样本树上右键类别 →「导出层级」即可单独指定该分支：

| 选项 | 含义 | 树上标记 |
| --- | --- | --- |
| 默认 | 整支被勾选则合为一个文件，只勾一部分则下钻到子类别 | 无 |
| 整支合并为一个文件 | 该类别整支作为一个单元，即使只勾选了其中一部分 | `[合]` |
| 按子类分别成文件 | 该类别自身不成文件，改为下钻到子类别，即使整支都被勾选 | `[分]` |

标记只作用于所在分支，其余分支仍按默认规则；标记与勾选状态相互独立，
「全选」「按 ROI 选择」这类批量操作不会把它冲掉。工区节点右键可一次清除全部标记。
上例把第四系标为「按子类分别成文件」后即得到 3 个文件：沉积岩、洪冲积、冲积。

输出文件的属性字段：`class`（整型标签号）、`class_code`、`class_name`、
`class_path`（完整层级路径）、`region`、`type`、`source`、`sample_id`。

**`class` 按本次实际写出的类别从 0 连续排，不沿用库内的类别号。** 库内的类别号
是对整库编的，只导其中几类时必然留出空号（比如只挑了 2、5、9 三类），下游拿它
当标签建 N 类分类器就会多出几个永远没有样本的类。跨工区导出时也是同一个计数器
一路排下去，不会两个工区各自从头编、编出重号。库内的类别号仍完整记在
`class_code` 字段与 `description.json` 的 `label_code` 里，对应关系不会丢。
裁剪样本块的标签号用的是同一套规则。

**文件名上的号就是这个标签号。** 默认模板 `Label_{label}_{name}`，`{label}` 与
文件里的 `class` 字段、`description.json` 的 `label_id` 完全一致。要用库内的类别
号请写 `{code}`——但那样文件名会跟文件内容对不上：库内号 19、23、26 的三个类导出
后文件名跟着跳号，而 `class` 字段是 0、1、2，人工核对时全乱套。

**一个基础类别只装一种几何**（点或面，见第 6 节），所以正常情况下一个导出文件
只有一种几何。老库里点面混着的类别、或按第 N 层把点类与面类汇总到一起时，
**拆成两个文件导出，共用同一个标签号**，文件名后缀 `_point` / `_polygon`——一个矢量
文件只能装一种几何，把其中一种丢掉就是无声的样本丢失，覆盖校验只会报"数目对
不上"，样本却已经不在结果里了。

**点要素可以按距离缓冲成面。** 一个点样本往往代表野外的一处观测，训练时要的是
它周围一小片地面。导出对话框里勾上「点要素缓冲」、填半径（默认
`config.BUFFER_RADIUS_M` = 30 m），点就扩成这个半径的圆以面写出；**重叠的圆合成
一个面**（同一处露头上的两个观测点不该变成两条互相压着的记录），覆盖校验按合并
后的数目算，`description.json` 记下 `buffer_radius_m`。只对点做，面不受影响；
可以只对某几个类别做——清单列的是本次导出涉及的、持有点样本的基础类别，缓冲针对
的类别与导出针对的类别就是同一批。圆在按这批点中心选的 UTM 带里画，30 m 级的
变形可以忽略。裁剪用的是同一套（见第 5 节）。

**导出目录是一个整体。** 往同一个目录重导一次少几类的结果时，上一次导出、这次
没有再生成的文件会被删掉，并在报告里列出删了哪些。旧文件留着的话，目录与
`description.json` 自相矛盾——描述文件里没有它们，再导入回来却会把过时的类别
一并读进去，凭空多出样本。只清理上一份 `description.json` 登记过的文件，
使用者自己放在目录里的东西一概不碰。

勾选「额外写出导入时保存的原始属性字段」后，按属性导入的样本会把原始属性表
逐字段还原到输出文件中。输出目录同时生成 `description.json`，记录导出层级、
各类别的层级路径与被合并的子类别，可被本程序再次导入。
文件命名模板可用 `{label} {code} {name} {region} {type} {date} {parent} {path}`。

导出目录里的文件一律**不带前导点**：点开头在资源管理器、Finder 和 `ls` 里默认都是
隐藏的，而描述文件恰恰是最需要打开核对的东西。早期版本写的是 `.description.json`
和 `.datasets.txt`，导入与训练时两个名字都认，老目录不用动。

```python
from samplelib.session import LibrarySession

s = LibrarySession(); s.open("地质样本库.gpkg")
s.export("out_leaf", level="leaf")                                   # 末级类别
s.export("out_lv2",  level=2, name_template="{path}")                # 第 2 层
s.export("out_pick", level="custom", unit_class_ids=[12, 34, 56])    # 指定单元
```

## 5. 裁剪样本块

把样本裁成深度学习要的影像块：以每个样本位置为中心，从影像上切一个
`patch × patch` 的方块，配一个标签。菜单「导出 → 裁剪样本块…」，或工具条上的
裁剪按钮。

输出格式有两类。**`h5`（推荐）所有块进一个文件**：

```
输出目录/
├── train_dataset.h5             全部训练块 + 标签 + 类别名 + 源影像信息
├── test_dataset.h5              训练集比例 < 1 时才有
└── labels.json                  标签 ↔ 类别对照表
```

文件内部：`patches` (N, 波段, patch, patch)、`labels` (N,)、`centers` (N, 2)
每个块中心在源影像上的行列号、`label_names` 标签对应的岩性名，以及 `attrs` 里的
形状、dtype、源影像路径与 geotransform。`patches` 的 chunk 按**一个样本**切，
取一个块只读一个块，不会把整个数据集加载进内存。

`bin` / `tif` 则是一个块一个文件：

```
输出目录/
├── train_dataset/
│   ├── img_label0_1.bin ...     块文件，边缘不足处补 0
│   ├── datasets.txt             每行「路径 标签」
│   └── raw_bip_meta.json        bin 的形状与类型（layout/bands/height/width/dtype）
├── test_dataset/                训练集比例 < 1 时才有
└── labels.json                  标签 ↔ 类别对照表
```

三种格式切出来的块逐字节相同，只是装法不同。`bin`/`tif` 这套输出与项目里
`split_and_clip_dataset` 那条链路完全一致。

`Train.py` / `Models/Data.py` 都可以直接拿去用：把输出目录整个交给 `Train.py` 的
第一个参数，它会自己看目录里是 `train_dataset.h5` 还是 `train_dataset/`，分别用
`Models.Data.HDF5_Dataset` 和 `CNN_Dataset` 读；分类数由 `labels.json` 给出，
不必自己数。切块的窗口计算、边缘补零、地理变换改写
都照搬 `aircasgxt_core.gdal_utils` 的原实现，没有改动其数学——点样本与面样本、
单波段与多波段、tif 与 bin 共 8 种组合都做过逐字节比对，结果与原实现完全相同；
`h5` 的块也与 `bin` 逐字节比对过。

### 为什么默认推荐 h5

一次裁剪动辄几万到几十万个块，`bin` 就是几十万个小文件：拷贝、备份、传给别人
都很慢，形状还挂在外面的 `raw_bip_meta.json` 里，一分家就成了一堆没有形状的
字节。`h5` 把这些收进一个自描述的文件。实测（12000 个 150 波段 17×17 的块、
4 个 DataLoader worker、页缓存清空）：`h5` 每秒 25422 个样本，一个块一个文件的
`bin` 是 15888——单文件不但好管，冷读还更快。

`h5` 可以压缩，见 `samplelib/config.py` 的 `CLIP_H5_COMPRESSION`。默认 `none`；
设成 `zstd` 能压到约 57%（需 `pip install hdf5plugin`，**读的一侧也要装**，缺包
时会自动退回不压缩并在结果里提示）。`lzf` 对高光谱几乎不压，别用。

**裁剪半途出错不会留下半个样本集。** h5 写到一半的文件会被删掉——它有 `patches`
却没有 `count`、`dtype` 这些属性，读的一侧只会报一句"样本集是空的"，谁也想不到
是上一次裁剪崩在中途；句柄不关在 Windows 上还会把文件锁住，重裁都覆盖不了。
`bin` / `tif` 已经落盘的块留着不动（各自都完整），但不写样本清单，下游就不会
把这批残缺数据当成一份可用的样本集。

**中途取消与出错不同：**已裁出的块保留，清单照写，但 `labels.json`、`raw_bip_meta.json`
与 h5 的属性里 `complete` 记为 `false`，报告里也点明只裁了几类——一份少了几类的
样本集看起来与完整的一模一样，是最容易被拿去训练的那种错误。

**往同一个目录重裁是一个整体。** 块文件按「前缀_label标签_序号」命名，重裁一次
类别更少的结果时旧文件只被覆盖一部分，剩下的留在目录里，按文件名扫目录的读取
代码会把过时的块也读进去。因此开始前先删掉上一份 `datasets.txt`（新旧两个名字都
认）登记过的块文件，使用者自己放进去的东西不碰。

**测试集整个为空会明确提示。** 按要素划分时每个类别只有一个面，就会全部归到训练
侧，`test_dataset.h5` 是个 0 样本的空文件，直接拿去训练只会得到一句"样本集是
空的"。结果摘要里会点明这一点，并给出三条出路：调低训练集比例、改成按像元划分、
或者把比例设成 1.00 只出训练集。

### 参数

| 参数 | 说明 |
| --- | --- |
| 影像 | 要裁剪的栅格。必须带地理参考，否则无法把样本位置对到像素上 |
| 块大小 | 方块边长（像素），常用 13-30。偶数时中心偏左上 |
| 输出格式 | `h5` 所有块进一个文件，好拷好管，训练首选；`bin` 一个块一个文件，体积小但文件极多；`tif` 一个块一个文件，带地理信息，便于逐块核对 |
| 训练集比例 | 1.00 表示不划分，全部写入 `train_dataset` |
| 划分方式 | 见下 |
| 只裁当前勾选的样本 | **默认勾上**，与「导出样本」一致。取消后裁整个样本库 |
| 裁剪层级 | 与导出同一套口径，一个单元一个标签 |
| 点要素缓冲 | 勾上后点样本扩成半径 R 米的圆再裁：圆内每个像元一个块，重叠的圆合成一个要素（按要素划分时整体归一侧）。可只对某几个类别做；不勾则一个点一个块。`labels.json` 记下 `buffer_radius_m` |

「只裁当前勾选的样本」默认开着：裁剪几乎总是接着"在树上挑出这次要用的类别"
这一步来的，默认把整库裁一遍动辄多出几十万个块，等跑完才发现不对。要整库裁的
话自己取消这个勾选。

### 三处与原链路不同

**坐标系**　样本库统一存 EPSG:4326，原链路只做反地理变换、不重投影。影像若是
UTM，经纬度算出的像素位置会全部落到影像外，而越界位置是被静默跳过的——于是
「跑完不报错、输出空目录」。这里在取像素位置前先做坐标变换，影像缺地理参考时
直接报错，不产出空结果。

**标签**　原链路的标签是目录里 shapefile 的枚举序号，换台机器或改个文件名就会
变。这里的标签由类别层级决定，并随输出写一份 `labels.json`：哪个标签对应哪个
岩性、由哪些类别合并而来、各裁出多少块，都记在里面。标签号从 0 连续排，且只发给
**真正裁出了块**的类别——某个类别的样本全落在影像范围外（或本次没勾中它的样本）
时，它不占号，只在报告里给一条提示，否则 `labels.json` 里会留一个永远没有样本
的标签。

**训练/测试划分**　原链路对面样本是**按像元**随机划分的，同一个露头的相邻像元
会同时落进训练集与测试集，测试精度因此偏乐观。这里默认**按要素**划分，一个面
整体归训练或测试；需要复现旧结果时在「划分方式」里选「按像元划分」。

切分点保证两侧都不为空。按比例直接取整会在划分单位很少时把一侧切空——一个
类别只有一个要素时 `int(1 × 0.6) = 0`，该类别就完全没有训练样本，而标签仍在
`labels.json` 里，模型永远学不到它。确实只有一个单位、切不出测试集时，整份
归训练侧并在结果提示里点名说明。

裁剪读的是样本库文件本身（另开一份只读连接，因此界面不会被卡住），裁的是**已经
落库**的样本；标注模式里还没落库的暂存编辑不会被裁进去。单个类别默认最多取
50000 个像素位置——一片大面能覆盖几十万像元，全裁出来既慢又让类别严重失衡，
上限在 `config.py` 的 `CLIP_MAX_POSITIONS`。

## 6. 界面功能

* **样本树**：工区 → 分组（任意多级）→ 基础类别。树上只有两种节点：**分组**是
  层级容器，自身不存样本；**基础类别**是树的末端，直接持有样本、**只装一种几何**
  （点或面），不再往下展开——样本在画布上看、在画布上选。「选」列支持三态勾选
  （☑ 全选 / ◪ 部分 / ☐ 未选），勾选分组会连同其下所有类别。检查器里能看到
  基础类别的种类（点 / 面 / 未定——新建后还没画过样本的类别，第一条样本画进去
  是点它就是点类）。
* **老库里"自己有样本、下面又挂着子类别"的节点**：1.1 之前没有分组这个概念，
  沉积岩自己可以有 3 个点、下面还挂着砂岩、泥岩。打开时升级到 1.2：在它下面
  建一个**同名**的基础类别「沉积岩」装那 3 个点，它自己改成分组——树上看就是
  "沉积岩 → 沉积岩 / 砂岩 / 泥岩"，样本一条不少，谁的还是谁的；自己那份点面
  都有的拆成「沉积岩（点）」「沉积岩（面）」。新类别沿用父节点的类别号（因此排在
  兄弟最前）、颜色、来源与属性，不重编整个工区，树上也不带「•」。自己没样本的
  父节点只改成分组，不多建类别。
* **标注只能在基础类别上进行**：树上高亮分组时画布拒绝落笔并说明；往点类里画面、
  把点要素改归到面类，同样被拒绝——一个类别里点面混着，导出要拆两个文件、裁剪
  要按两套规则算，谁也说不清这个类别到底是什么。导入时点面混着的文件会拆成一个
  分组下的「名（点）」「名（面）」两个基础类别。
* **在树中自定义分级**：右键菜单可重命名类别 / 工区、编辑说明、在分组下新建类别
  或分组、移动到别的分组、删除。改动过的节点标有「•」记号。
* **拖动既能改层级，也能只调顺序**，靠落点区分：拖到一个**分组**的中间是成为
  它的子类；拖到一个**基础类别**的中间是**两者升一级**——在那个位置建一个新分组
  （会问分组叫什么，默认就用基础类别的名字），把两者都装进去，基础类别自己不能
  再有子类别；拖到两条之间是**与目标同级、插到那个位置**，拖到工区标题上是迁到
  该工区的顶层。**跨工区照样拖**：拖进另一个工区的分组、拖到那边两条之间、拖到
  工区标题上，整支连样本一起换工区（拖到两条之间早先只换了顺序没换工区，树一
  刷新又回到老地方，看着像拖不动）。这些都进撤销栈，改错了 Ctrl+Z 就回去了。
* **改完树不跳。** 树是样本库的投影，每次编辑落库后都整棵重建。重建前记下视野
  最上面那一行和它离顶边多远、以及当前行，重建后按那一行对回去：上面多了或少了
  几行都不影响，正在看的那一片原地不动，被拖动 / 改名的那一类仍是当前行，检查器
  也不会退回库概览。
* **Ctrl+C / Ctrl+V 复制样本**（右键菜单里也有）。选中一个基础类别、分组或工区
  按 Ctrl+C，再选中目标按 Ctrl+V：目标是**工区**或**分组**，复制整支——新类别、新
  样本，排在目标的末尾，同名的按「泥岩1」的规矩起名；目标是**基础类别**，把来源
  的全部样本复制进去（几何种类得一样，点类别不收面）。复制工区就是复制它的全部
  顶层类别。粘完目标仍是高亮的那一行，连着粘几次就是几份。一步可撤销。
* **树上不显示类别编号。** 早先每个类别前面带一个 `[7]` 这样的号，还能改、能
  按顺序重排——那个号只是这棵树的排序键（`code`，拖动调顺序时后台自动重编，
  记住顺序用的），给人看没有意义：真正有用的编号是导出 / 裁剪时按导出单元从上到
  下 **0 起连续排**的标签号，导几类就编几个，不会因为只挑了其中几类留出空号。
  于是编号、「修改类别号」「按当前顺序重排类别号」一并从界面上拿掉，检索也不再
  按它匹配。
* **检索**：按 类别名 / 工区 / 样本类型 / 分类属性值 实时过滤，
  可以直接用「火山岩」「奥陶纪」这类属性值检索。
* **画布**：滚轮缩放、左键拖动平移、双击全图，带经纬网与比例尺；
  缩放**按滚轮的实际增量取幂**（`ZOOM_STEP ** (delta / 120)`）而不是每个事件一整
  格：触控板一次划动会推出几十个小增量，每个都按一整格算的话，手指轻轻一划就放大
  十几倍。普通鼠标一格仍是 120 个单位、仍是 1.25 倍，触控板的碎增量按比例缩成一
  点点，单次事件封顶两格；
  单击样本可切换选中状态（Shift+单击为追加）。与标注模式是同一个画布，只是
  以只读模式构造，因此**同样支持叠加影像图层、在线底图与拖拽加载**，但工具只有
  平移与选择，画不了也改不了几何——绘制与编辑要切到标注模式（见第 9 节）。
* **画布默认只显示勾选中的样本**。整库上万条一次全铺出来只会糊成一片，勾什么
  看什么才读得出信息；一条都没勾时画布上会写明原因，而不是留一片空白让人以为
  坏了。要看全部样本，在「视图 → 只显示勾选的样本」里关掉即可（标注模式下一条
  没勾时程序会临时替你关掉，回浏览自动还原，见第 9 节）。**点选、框选、右键、
  捕捉只碰画出来的样本**：被这个过滤藏起来的、样本图层整层关掉的，一律点不中、
  框不中；取消勾选时，已经选中的那些也随之移出画布选中。想在画布上从整库里挑
  样本，先把这个过滤关掉。
  **还没保存的草稿不受这个过滤管**：草稿不在库里，样本树上没有它，也就无从
  勾起，拿这个过滤器去筛它没有任何道理。见第 13 节。
* **要素信息**：右栏检查器下面那一块，与检查器按 3:2 分高度（属性表字段多，它占大头；
  拖过分隔条之后按你拖的尺寸记住）。平移或选择工具下在画布上单击一处，那里
  压着的矢量要素连同全部字段值列在这里——参考矢量、手绘范围、样本都算，影像
  不算（像元光谱用取谱工具）。多个要素叠在一起时**按图层清单自上而下**列，同一
  图层里点、线在前，面按大小从小到大；关掉的图层、没勾的样本看不见，也就不列。
  当前指着的那个要素在画布上用虚线框标出，点面板里别的要素，虚线框跟着换。
  虚线框的世界坐标只在换要素、换投影时算一次，每帧只描视窗附近那一截：一个上万
  顶点的岩性图斑，拖动时不必每帧重新投影、重新描整圈。它只
  是"看"：样本的选中仍由画布点选决定，点选挑中的那条正是面板里列在最前的样本。
  字段行可多选后 Ctrl+C 复制（制表符分隔，可直接粘进表格）。
* **光谱曲线**：右键影像图层「光谱曲线…」，弹出独立窗口，在图上点哪读哪，多条
  曲线可以叠着比，出图直接是论文能用的样子。画布上没有影像时也能从「视图 → 光谱
  曲线…」打开，用来翻光谱库、导入 CSV、出图。单列一节讲，见第 7 节。
* **起名带地质符号**：新建 / 重命名类别与分组、给样本命名、用选中要素新建类别时，
  输入框下面有一块符号面板——地质年代（``T₃``、``Qp₁``、``Pt₂``、``J₁₋₂`` 一下点出
  完整代号）、岩石代号（``ηγ`` 二长花岗岩、``γδ`` 花岗闪长岩……）、第四系成因
  （``ᵃˡ`` 冲积、``ᵖˡ`` 洪积……）、希腊字母、离子与常用符号，最近用过的排在最上面。
  上下标与 Word 一样两种用法：选中文字按「下标 / 上标」就地转换（再按一次转回）；
  不选时按一下进入下标 / 上标输入状态，接着打的字直接是下标 / 上标。快捷键
  ``Ctrl+=`` 下标、``Ctrl+Shift+=`` 上标（macOS 上是 ⌘）。上下标存成 Unicode 字符，
  名字仍是普通文字，导出的文件名、属性表、labels.json 原样带过去；检索时上下标
  折回普通字符，打 ``T3`` 就能找到 ``T₃``。Unicode 没有的写法（如大写 Q 的上标、
  b、c、d 的下标）按原样保留，并在框里说明。
* **感兴趣区**：画一个，或者拿画布上现成的矢量图层；影像图层可以生成它的覆盖范围，
  并可作为画布底图显示。筛选方式支持 相交 / 完全包含 / 中心点在内。
* **在线底图**：菜单栏「底图」或工具条上的底图下拉，天地图 / Mapbox /
  OpenStreetMap 都可以垫在画布下面，两种模式共用同一套菜单与同一份瓦片缓存。
  只看样本点分布时没有底图就只能对着空白画布猜位置。
* **状态栏右侧常驻计数**（类别数 / 样本数 / 已选条数与类别数）。左边那条提示随时
  会被下一句冲掉，统计放在那里等于看两眼就没了。
* **状态栏最右是显示坐标系**，点它就换。除 WGS 84 / CGCS2000 / Web 墨卡托外，
  还会按当前视野中心算出该用哪个 UTM 带并排在最前（比如在都兰是
  `WGS 84 / UTM zone 47N`），也可以直接输入任意 EPSG 代号。选投影坐标系后
  读数按米显示，选经纬度按度显示。

  **画布跟着一起换投影。** 选 UTM 之后画面就是这个带的投影：等经度线不再是竖直
  的，影像重采样到该投影的格网上，比例尺按米直读。只换读数不换画面的话，选投影
  这件事没有意义。

  **它只改显示，不动数据。** 样本库里的几何一律存 EPSG:4326（第 2 节），换显示
  坐标系不会重写任何东西，也不影响导出——导出的坐标系在导出对话框里单独选。

  **每次启动都从 WGS 84 起步。** 显示坐标系是"这会儿想怎么看"，不是样本库的
  属性，因此不写进会话状态：上次为了量个距离切到某个 UTM 带，下次开另一个库时
  不会迎面撞上一个跟数据毫无关系的坐标系。会话状态里记的视野是
  **经纬度直投下**的一组 `(cx, cy, scale, k)`，与当时用哪个投影显示无关——
  绑在某个投影的米上，换个坐标系再打开视野就飞到别处去了。

## 7. 光谱曲线

右键画布上的影像图层 →**「光谱曲线…」**（或命令条上那个折线图按钮），弹出一个
**浮动窗口**，画布同时切到**取谱**工具。

**没有影像也能打开。** 从「视图 → 光谱曲线…」进来时画布上一幅多波段影像都没有，
窗口照样打开、只是不绑图层：翻光谱库、把库里的谱叠在一起比、从 CSV 导入曲线、
出图都用不着影像。这时不切到取谱工具（点了也读不出东西）；之后加载了影像，点
命令条上的「取谱」就会把窗口绑上去。只有「按类别取平均谱」必须有影像，没绑时
它会说明怎么绑。之后在影像上单击，该位置的整条谱立刻
画出来；**Shift 单击**把当前这条留在图上，接着点下一个位置，几条谱叠在一起比。
取谱工具下**拖动仍然是平移**——要读一条谱总得先把目标找出来，为此在两个工具之间
来回切，一次取样要点四下。

**为什么是浮动窗口而不是停靠栏。** 取谱要一边在影像上点、一边盯着曲线看，停靠在
主窗口底部时这两件事抢的是同一块屏幕：面板拉高一点画布就矮一截，想同时看清两边
只能来回拉。浮动窗口压在画布上方，可以拖开、拉大小，位置由使用者定，
也不挡住别的操作。

布局参照 ENVI 的 Spectral Profile：上面是菜单与样式栏，中间是图，底下一行选横纵轴。

| 位置 | 内容 |
| --- | --- |
| 导入 | 从 CSV 读回曲线（读的就是本窗口导出的那种表） |
| 导出 | 导出图（PNG / PDF / SVG / EPS / TIFF）、导出数据（CSV）、复制图片 |
| 选项 | 水汽波段、诊断吸收位置、坐标全框、次刻度、衬线字体、图例位置、图例列数、字号、位图精度、图标题、诊断吸收特征表 |
| 样式栏 | 线宽（滑块）、数据点（自动 / 总是 / 从不 + 大小）、配色（带色卡）、图幅、网格、图例 |
| 底栏 | X（波长 / 波段序号）、Y（纵轴单位）、范围、取谱窗口，右端是鼠标浮标的读数 |

**常用的不藏进菜单。** 线宽粗一点、数据点大一点、换套配色——这些是"看着图随手调"
的东西，每次都去菜单里翻一遍太笨，所以单独占一条样式栏，用滑块与数字框拖着看
效果。剩下那些设一次就不动的（字号、次刻度、图例位置…）才留在「选项」里。

**曲线清单默认收起。** 绝大多数时候图上一两条曲线，看图例就够了，那一栏只是白占
三成宽度；要改名、单独换颜色时点右上角「曲线清单」调出来。

**清单里列的是图上每一条，包括"当前"那条**（名字后面标着「（当前）」）。清单下面
一排「改名… / 颜色… / 删除」，选中按 **Delete** 也能删，可以一次选好几条——删曲线
是个随手动作，不该逼人去翻右键菜单。原来当前
那条不列，理由是它还在动、给它一行只会一直闪；但那样它就成了唯一一条改不了名的
曲线——在影像上点出来一条觉得有用，想在图例上写清楚它是哪儿的，只能先钉住再改，
而钉住这个动作本身又把"当前"让给了下一次点击。清单里的操作按**曲线对象**走而不是
按行号走，删一条、钉一条都不会串到别人身上。

**改单条曲线的颜色，直接在图上点那条线。** 光标一靠近，那条线就套上一圈光晕、
鼠标变成小手，看得出它可以点；原地按一下就弹取色器。不必先去清单里找它是第几条。
清单的右键菜单里也有一份，外加「恢复默认颜色」。第一条曲线默认是红的——单条曲线
的图占绝大多数，而单条用红最惯常。

**颜色跟着曲线走，不跟着它排第几走。** 每条曲线进图时分到配色轮上的一格
（`Spectrum.slot`），此后不再变。按位置算颜色的话，从光谱库里加一条进来，前面那些
的名次一动颜色就全变一遍——尤其是"当前那条"，它排在所有钉住的后面，每加一条就换
一个颜色。删掉中间一条同理，剩下那些不该跟着换。换整套配色仍然是整体生效的。

**看某一段波段有三条路**：底栏「范围」下拉里的预设、下拉最后一项「自定义」手输
起止、或者**直接在图上横向拖出一段**（按下之后要挪出六个像素才算拖，之内的都当成
"我在点这条曲线"，见第 8 节「曲线的三个手势」）。双击图回到全谱。换范围时**纵轴跟着这段里的
数据重新定**——放大到短波红外还挂着全谱的纵轴，那一段的起伏会被压成一条直线，等于
没放大。

下拉里 F1~F5 那几档除了跳过去，还会**把那个判读窗口铺上底色并写明是哪一段**（就是
论文插图里那种浅色竖带）。"我在看这一段"和"这一段是哪一段"本来就是一件事，分成两处
开关只会让人调完一处发现另一处没跟上。

### 取数

| 环节 | 做法 | 不这么做会怎样 |
| --- | --- | --- |
| 定位 | 经纬度先投到影像自己的坐标系，再走逆仿射换行列号 | 影像不是经纬度存的（UTM、Albers 都常见），直接拿经纬度套仿射，点会落到几百公里外 |
| 无效值 | nodata、Inf、以及**整景恒零的坏波段**一律换成 NaN | 换成 0 会在曲线上拉一根到底的尖峰，还把纵轴范围整个带偏 |
| 定标 | 按 GDAL 波段自带的 scale / offset 换算 | ENVI 与部分 GeoTIFF 把反射率缩放记在这里，忽略它读回来的是 0~10000 的整数 |
| 窗口 | 可选 1×1 ~ 9×9，窗口内求均值，无效值不参与 | 单像元噪声大；但窗口跨过地物边界就会把两种地物混在一起，所以默认 1×1 |

**横轴优先用波长。** 影像自带 ENVI 头里的 `wavelength` 就用它，没有则退回波段
序号，窗口里会写明。传感器波长表可以在「图层属性」里加载（第 6 节的影像图层），
加载后横轴立刻变成纳米。波长乱序时（拼接过 VNIR/SWIR 的产品常见）按波长重排，
否则曲线会在接缝处来回折返——重排时波段号跟着一起搬，横轴切回"波段序号"时对得上。

#### 横轴是**这张图**的属性，不是那幅影像的

横轴画什么，由图上现在有哪些曲线决定，每次重画都重新问一遍：

| 图上的曲线 | 横轴 | 下拉框 |
| --- | --- | --- |
| 一条都没有 | 按绑定影像能给出的那种 | 只有一种可选时禁用 |
| 全都自带波长 | 波长 | 两种都可选 |
| 有一条没有波长 | 波段序号，并在说明行写明为什么 | 禁用 |

这条规则是被一个具体的场景逼出来的：**拿一幅 JPG 打开曲线窗口，一个点都没取，
只从光谱库里调两条标样出来看。** 从前 `bind()` 一锤定音——影像没有波长表就把横轴
锁死在波段序号上、下拉框直接禁掉，于是库里明明自带 nm 的谱被摆到 1..N 的序号轴
上，两条采样密度不同的标样根本对不齐；而水汽标灰、诊断吸收位置、判读窗口高亮
**都以"横轴是波长"为前提**（`plot.draw_into` 里那一句 `"Wavelength" in xlabel`），
于是一并失效。三个症状，一个根子。

下拉框接的是 `activated` 而不是 `currentIndexChanged`：前者只在**人动手选**时才发。
横轴选项会随曲线增删而变，程序自己把下拉框拨过去时不能记成使用者的选择——否则拿
一幅没波长的影像开窗口、下拉框被拨到"波段序号"，之后每一条自带波长的谱都要跟着
它一起挤在序号轴上。没明确选过就按波长，那是信息更多的一种。

#### 影像没有波长标记时

高光谱产品的 ENVI 头里少了 `wavelength` 是常事。这时：

* 横轴按波段序号，曲线的形状照样有意义，只是读数换了；
* 说明行写清"影像没有波长表"以及下一步——在「图层属性」里加载传感器波长表
  （`config.WAVELENGTH_DIRS` 下按波段数吻合筛出候选，波段数对不上一律拒绝：
  拿一份 166 波段的表去套 330 波段的影像只会得到错的波长）；
* 加载之后**已经取过的那几条谱一并换到波长轴上**，不必把点重新点一遍——取谱时
  `Spectrum.bands` 一直留着每个点对应哪个波段，照新表一查就换过来了（`relearn_axis`）。
  换完按波长重排，横轴范围也放回全谱：旧的那一段是按波段序号设的，换成 nm 之后
  没有意义。

拿不到波长表也不影响别的：曲线照画、平滑照做、可以存进「我的光谱」。只有需要
波长对齐的那几样——水汽标灰、诊断吸收位置、与光谱库做匹配——用不了，因为它们
本来就需要知道每个波段对应多少纳米。

**纵轴单位是个下拉，默认「自动判断」。** 浮点、且量程在 0~1.6 的按反射率原值读；
整数、量程在千位的按"反射率 ×10000"读；其余按 DN。猜错没有后果——下拉就在旁边，
而且写着"自动判断"，一眼能看出这是个猜测。

### 水汽区间与诊断吸收特征是数据，不是常量

这两组数会随传感器与研究区调整，改一个中心波长不该动源码，更不该等一次发版。
所以它们写在一个 JSON 里（`samplelib/data/spectral_features.json`），启动时读：

```json
{"key": "F4", "name": "Fe–OH", "label": "Fe–OH",
 "centre": 2253.0, "window": [2230.0, 2310.0], "view": [2130.0, 2420.0]}
```

`window` 就是**做特征提取时用的那组边界**——图上标出来的范围与算法实际用的必须是
同一组，否则那张图是在骗人。`view` 是「范围」下拉跳过去时显示的那一段。名字存两份
的理由见下面出图那节（Arial 没有 Unicode 上下标字形）。

「选项 → 诊断吸收特征表…」会把这份文件复制到可写目录并打开所在文件夹，改完重启
生效。**写坏了整份退回内置的那份**，不逐条兜底：一份改了一半的定义比默认值更危险
——图上标的窗口与算法实际用的对不上，而且不会报错。

**水汽波段默认「断开并标灰」**：1324.5~1459.0 与 1795.5~1963.7 nm 这两段被大气
水汽吸收殆尽，反演出来的是噪声。曲线在那里断开，同时铺一条浅灰带说明为什么断。
这两个区间与诊断吸收位置一样是**领域事实**，只在 `samplelib/spectra.py` 里写一份，
绘图那边是拿来用的——两处各写一份迟早会不一致，曲线断开的位置与灰带对不上，图就
错了。

### 出图

**用 matplotlib**，样式对齐论文插图：7 pt 无衬线（Arial → Helvetica → DejaVu
Sans）、0.8 pt 轴线、去掉上右两条边框、无边框图例、极淡的横向网格、
`pdf.fonttype = 42` 与 `svg.fonttype = none`——**矢量导出里文字仍是可编辑的真
文字，不是轮廓**，丢进 Illustrator 能直接改。这些参数集中写在 `modules/spectra/plot.py` 的
`PAPER_RC`，屏幕与导出共用，改一处全都跟着变。

曲线图用 matplotlib 画而不是在页面里画：刻度算法、图例避让、约束布局、矢量后端
都是现成的，多出来的几十兆体积买的是"论文里长什么样，这里就长什么样"。

**屏幕与导出是同一份绘制。** 界面上那块画布挂的就是一个 `Figure`，导出时另建一个
同尺寸的 `Figure` 走同一个 `draw_into()`。画布锁定图幅的宽高比、四周留灰底居中，
不是把图拉满窗口；窗口一大图跟着**等比放大**——图幅、字号、线宽、轴线粗细同乘一个
系数（`PlotStyle.scaled()`），所以屏幕上看到的就是导出那张图放大的样子，比例一处
不差。只有一处例外：当前那条曲线在屏幕上画粗一点，导出时不粗。它是个游标，标的是
"再点一下会被换掉的是这条"，跟鼠标浮标的参考线同类，属于交互而不属于图。

学术制图上的几处默认：

* **配色三选一**：默认 tab10（绝大多数论文插图里的那一组）、Okabe-Ito 色盲友好、
  灰度（黑白印刷）。三套都在颜色用完一轮后**换线型**，灰度打印下仍能区分。
* **字号**默认 9 pt，6~12 pt 可选。期刊对插图内文字的下限通常在 6~7 pt，但那是
  **印在纸上**的尺寸；屏幕上看图、投影汇报、以及图幅本身不大时，9 pt 起步才读得
  舒服。同样的 12 pt 放在 90 mm 宽的单栏图里，相当于通栏图里的 6 pt。
* **图例可以挪到图右单独一栏**（「选项 → 图例摆放 → 图右单独一栏」）。曲线一多，
  图内的图例又压曲线又挤成一团；挪出去之后，那一栏**与曲线画布一样高，宽度按内容
  量出来**，图内也不用再为图例留顶部空白。两块仍在同一张 figure 上（并排两块
  Axes，`width_ratios` 按毫米给），所以**导出还是一个文件**——插进版面时图和图例
  本来就该是一体的。

  这里有个必须守住的规矩：**那一栏的宽度只跟内容和排印参数有关，跟画布在屏幕上
  多大无关。** `measure_legend_mm()` 拿一张离屏的图把图例排一遍量外接矩形，结果按
  （标签、字号、列数、线宽、标记）缓存。宽度一旦跟着画布的像素宽走，就会绕出
  "画布变宽 → 图例变宽 → 整幅更宽 → 画布再变宽"的正反馈，图会自己一点点长大——
  这个窗口在别处栽过一次，不能再来第二次。自测里钉着这一条：反复把窗口拉到
  1500 / 2000 / 860 再拉回来，图幅毫米数与窗口最小宽必须一个数都不变。
* **图例列数**在「选项 → 图例列数」里挑，「自动」是四条以上且图幅够宽时分两列。
  手动指定有两种场合：图例横着摆在图顶时列数决定它占几行高；曲线名长短悬殊时，
  自动那档挑的列数常常不是最省地方的那个。列数一变，纵轴顶部给图例留的空白跟着
  重算。单独一栏时「自动」的算法不一样：纵向是富余的、横向是贵的，所以先把一列
  填满再开下一列——多开一列，右边那栏就宽一倍，图跟着窄一截。
* **图例交给 matplotlib 的 `loc="best"`**，它会挑压住数据最少的位置；但它只会挑
  位置，不会替你把轴撑开，四五条曲线铺满整幅图时放哪都压线。所以图例每多一行，
  纵轴顶部就多留一点空白（上限 34%），让它有地方落。
* **横轴贴着数据两端不留边距**：光谱的两端就是传感器的量程，留白反而让人以为那里
  还有数据。
* **点数少于 30 个自动带上数据点标记**——十几个波段的多光谱影像画成光溜溜的折线，
  看不出采样位置在哪。
* **线宽与数据点标记都能调**。标记有三档：自动（点少时才画）、总是、从不。
  论文里那种"线 + 圆点"的画法把标记打开即可；几百个波段的高光谱打开会糊成一条带，
  所以默认是自动。
* **诊断吸收位置**（Fe³⁺ 511、Fe²⁺ 1014、Al–OH 2207、Fe–OH 2253、CO₃/Mg–OH
  2335 nm）可以画成竖点线**并标出名称**，用来对齐曲线上的吸收谷。
* **一次只高亮一个判读窗口**——五个窗口在短波红外挨着甚至叠着，一起铺出来能盖满
  整张图，等于什么都没标。
* **标注一律描一圈白边**（`path_effects.withStroke`）。H₂O 与诊断名称都竖在图顶，
  曲线爬上去时字就压在线上；描白边不动数据、不挪标注，字仍然读得出来。
* **图上的上下标一律走 mathtext**（`H$_2$O`、`Fe$^{3+}$`、`CO$_3$`）。Arial 与
  Helvetica 都没有 ₂ ³⁺ 这些 Unicode 字形，直接写出来是一串空豆腐块；mathtext 是
  把正常数字缩小挪位拼出来的，任何字体都成立。为此 `mathtext.fontset` 设成
  `custom`、`mathtext.rm` 指回 `sans`，数学与正文才是同一个字体。

图幅预设取自主流期刊的排版栏宽——单栏 90 mm、通栏 190 mm 覆盖了 Elsevier、IEEE、
Springer 的绝大多数模板。默认通栏 190 × 90 mm。导出不走 `bbox_inches="tight"`：
那会按内容裁边，出来的就不是要的物理尺寸了；图幅由 constrained layout 保证内容
全落在里面。CSV 导出是第一列横轴、其后每条曲线一列，横轴不一致时按并集对齐，缺的
地方**留空而不是补零**，读回来仍是 NaN。

**读数框最多列 10 条**，剩下的用一行「…还有 N 条」交代。十几条曲线一起列出来，
框子比图还高，把要看的地方全挡住了。

**鼠标浮标**在页面里画：后端出图时一并给出坐标映射（轴在图上的位置、横纵范围、
各曲线的采样点），鼠标一动只在前端算读数、画参考线与读数框，不必每动一下都回去
要图。浮标横轴对齐到**采样点**而不是鼠标的连续位置——光谱的横轴是
离散波段，读一个插值出来的数没有意义。

### 关掉窗口，工具跟着收回去

窗口一关就把取谱工具切回平移、擦掉画布上的标记。留着工具不收，画布看起来还能点，
点了却没有任何反应——窗口已经关了。影像图层被移除时同理：取谱器手里那个 GDAL
数据集还活着，不解绑的话点下去照样出曲线，而那条曲线来自一幅画布上已经看不见的
影像，比报错更难查。

## 8. 光谱库

取谱窗口上的「光谱库…」，或者「视图 → 光谱库…」（画布上没有影像也能打开）。库里
5008 条标准谱，矿物与岩石都有中文名，用来回答三个问题：**这条谱像什么？这一类矿物
长什么样？我自己测的这条以后还找得到吗？**

### 一个文件，不是一百一十个

ENVI 随机带的光谱库是 110 对 `.sli` / `.hdr`，散在五个目录里，一共 63 MB。直接
拿来用有三处不合适：

* **没有分类**。要"只跟矿物比"就得自己知道哪个文件装的是矿物；要"只跟层状硅酸盐
  比"完全无从下手。
* **量纲不齐**。ASTER 那套把反射率存成百分数（头里写 `reflectance scale factor
  = 100`），USGS 存成小数；USGS 还拿 `-1.23e34` 当无效值标记，照读会把曲线拉到
  天上去。
* **散**。进不了安装包，也没法当成一份东西版本化。

`tools/build_speclib.py` 把它们编译成一个 `samplelib/data/spectral_library.slb`：
反射率统一成小数、无效值统一成 NaN、每条谱带一条分类路径，float16 存值加 deflate
压缩，13 MB。它是个 zip，里面四样东西——

| 条目 | 是什么 |
| --- | --- |
| `manifest.json` | 版本、五套库的出处与引用格式、分类树、蚀变组合定义、数据块索引 |
| `index.json` | 每条谱一行：名字、分类、样品号、化学式、在哪个块的第几行 |
| `grid/<gid>.f4` | 一条波长轴（nm，升序） |
| `block/<bid>.f2` | 一批谱的值，行 = 一条谱 |

**值和索引分开放**是为了开得快：检索只用 `index.json`，13 MB 的数据块按需解压、
用完缓存。开一次库 0.02 秒，而不是把五千条谱全读进内存。**用 float16** 是因为它
的相对精度 5e-4，比任何一台地面光谱仪的重复性都高一个量级；float32 文件大一倍，
定点整数还得额外记缩放系数、NaN 还得另找一个哨兵值。

#### 量纲这条线要有人守

`manifest.json` 里写着 `value = reflectance`，那是这份库对使用者的承诺：**每一条
都是 0~1 的小数反射率**。这条承诺破过一次。

ASTER 那套里有一个 `mineral_jhu_nicolet_2287_transmit`，装的是 KBr 压片的
**透过率百分数**（0~100，个别到 121），而 ENVI 头里的 `reflectance scale factor`
老实写着 1——编库脚本照着头里的系数换算，一除以 1，130 条百分数原样进了库。表现
是：从库里调一条 Calcite 出来，纵轴读数在 20~110 之间，一条就把整幅图的纵轴撑坏，
同图上别的谱全被压成贴着坐标轴的直线。比这更糟的是光谱匹配——透过率与反射率是两种
物理量，把它当候选比出来的名次没有意义。

现在两处都拦：

* **编库时**（`build_speclib.MAX_VALUE_P95`）——一份文件的 `|y|` 95 分位超过 1.6
  就整份跳过，并在日志与 manifest 的 `skipped` 里点名；
* **对已经编好的库**（`tools/prune_speclib.py`）——同一条规则，就地把整块剔掉、
  重算分类树条数、在 manifest 的 `pruned` 里留痕，最后按使用者的读法复核一遍。
  原始 ENVI 目录未必还在手边，重编不了也得能修。

**为什么用 95 分位而不是最大值**：实测反射率在信噪比差的波段边缘冒到 1 以上是
常事——USGS 的 LawnGrass 在 2.7 µm 处到 2.0，那是测量噪声，不是量纲错，clip 掉它
就是篡改数据。真正存成百分数的块，95 分位在 90 上下，与小数反射率差着两个数量级，
一眼分得开。

剔掉那 130 条**没有丢矿物**：同一批样品的反射率谱就在隔壁的
`mineral_jhu_nicolet_2287` 里，91 种矿物名有 90 种同名（349 条），波长范围同样是
2.08~25 µm。唯一只在透过率文件里出现过的是变种名 alunite (ammonioalunite)，而
Alunite 本身还有三条。自测里有一节盯着这条线（`test_speclib.py` 第 20 节）。

收了四套：ASTER v2、USGS splib07a、IGCP-264、植被库。**USGS v6 默认不收**——v7
是它的后继版本，矿物部分 88% 的（矿物名, 样品号）在 v7 里都找得到，两套一起进库
只会让匹配结果里挤满同一条谱的两个版本。需要 v6 独有的那 59 个样品，把
`INCLUDE_SOURCES` 里加上 `"usgs_v6"` 重新编译即可。

窗口上的「出处…」列着每一套的完整引用格式。**论文里用到哪一套就引哪一套**，这是
使用条件，不是客套。

### 分类是从哪来的

这一点必须能交代清楚，否则树上挂的东西就只是一堆看着像那么回事的标签。

* **ASTER 的名字里自带分类**。它每条谱都写成
  `Actinolite Ca 2(...) [silicate-inosilicate-coarse-in04a]`，方括号里第一、第二段
  就是化学分类。岩石、土壤同理（`[igneous-felsic-...]`、`[mollisol-cryoboroll-...]`）。
  这是**源数据自带的**，占 3531 条。
* **USGS 与 IGCP 的名字里只有矿物名**。做法是先从上面那份 ASTER 的名字里收出一张
  「矿物名 → 化学分类」表（267 个名字），再拿矿物名去查。查着的与上一条记在一起，
  都算 `aster`——归类的依据同样是源数据。
* 查不到的那一百来个（allanite、halloysite、diaspore 之类），用
  `build_speclib.py` 里手工补的 `MINERAL_CLASS` 表，按矿物学通行的阴离子分类填写，
  逐条可核对，占 316 条。**填不准的宁可留空**，落到「未分类」——现在只剩 5 条。
* 岩石、土壤、植被这些按文件名的材料大类走，占 1280 条。

每条谱都记着自己的分类是哪来的（`csrc` 字段：`aster` / `curated` / `file`），
将来发现哪一条归错了，能直接定位到是源数据的问题还是手工表的问题。

**「蚀变组合」是另一回事**：泥化、高级泥化、绢英岩化、青磐岩化、碳酸盐化、硅化、
矽卡岩化、铁染、蛇纹石化九组，按经济地质里通行的蚀变分带矿物组合归的堆，一个矿物
可以属于好几组（明矾石既在高级泥化里，绿泥石既在青磐岩化也在矽卡岩化里）。它
**不是矿物学分类，是检索的捷径**，所以在树上单列一支，库文件里也存成独立的
`alt` 字段，不跟 `cls` 混在一起。

### 匹配：候选就是列表里那些

窗口底栏那一行。**拿去比的候选，就是此刻列表里的那些条目**——这正是分类树存在的
理由。跟五千条谱挨个比一遍，头几名多半是些八竿子打不着的东西；先框到「矿物 /
层状硅酸盐」再比，结果才读得下去。

候选不设上限：按当前的检索词与选中的分类把命中的全部拿去比，列表里列的也是全部
命中。分类树上每一支、每个蚀变组合、「全部」后面的条数都是打开时按库里现有条目
现算的，不是库文件里记的那份——往「我的光谱」里存谱、挪分类之后跟着变，与点下去
列出来的条数一致。

四个算法：

| 算法 | 脾气 |
| --- | --- |
| **SAM** 光谱角 | 把两条谱当高维向量算夹角。与整体亮度无关，地形阴影、照度差异都不影响它。默认。 |
| **SCM** 相关系数 | 去均值后的余弦（Pearson）。对加性偏差更钝，代价是**连吸收深浅也一并扣掉**——把吸收深度减半，它仍然给 1.0000。 |
| **SID** 光谱信息散度 | 把谱当概率分布算对称 KL 散度。对吸收深度比 SAM 敏感，对噪声也更敏感。 |
| **SID×tan(SAM)** | 两者相乘，区分度最高，也最挑数据质量。 |

**这里没有欧氏距离，是故意的。** 归一化之后的欧氏距离恰好是 `2 sin(SAM/2)`，与
SAM 单调等价；改成除以均值再算均方根差也一样——拿全库 1825 条矿物谱实测，两者
名次的 Spearman 相关是 0.99999，在"同形状、吸收深度减半"的构造样本上给出同一个数
（0.0370 与 0.0371）。多列一个只会让人以为多了一种判断依据。

比之前有三步固定动作：

1. **对齐**。库谱线性插值到影像的波长上。反过来把影像插到库上是无中生有，而且比
   一次要算五千遍。插到源波长范围之外的点给 NaN，不外推。
2. **包络线去除**（默认开）。先把曲线的上凸包当基线除掉，剩下的是纯吸收深度与
   位置。不去包络，排在前面的往往只是"亮度差不多"的东西。
3. **剔水汽段**（默认开）。1400 与 1900 nm 附近影像上是噪声，留着会主导相似度。

还有两道闸门：参与比较的有效波段至少 12 个，且要占查询谱的三成以上。只在边角上
重叠一小段的谱，算出来的角度很小、排名却能冲到前面，是最常见的假第一名。「能盖住
影像波段」那个勾在检索这一层就先把它们滤掉了。

四个算法的量纲不一样（角度、相关系数、散度），所以都折算成 0~100 的得分。折算不是
随手挑的：两条谱差别很小时 SID 大致按夹角的**平方**增长、SID·tan(SAM) 按**立方**
增长，所以先给它们开二次、三次方根还原成"等效夹角"，再套 SAM 那个折算式。这样四个
算法的得分才落在同一个量级上，不至于 SID 那一栏前二十名全是 100.0。开方是单调的，
排名不受影响。**得分只在同一个算法内部有意义，跨算法不可比。**

### 我的光谱

自己的谱存在 `my_spectra.slb`（在可写目录里，不入版本库）。格式和随包那份完全一样，
因此同一套读取代码、同一个检索入口、同一棵树：存进去之后照样能搜、能当参照、能参与
匹配。分类树上它排在「全部」下面第一支，自己建的分类都挂在这一支里。

**存。** 取谱窗口里曲线清单上右键「存入我的光谱库…」（选了几条就存几条），或者
「导出 → 存入我的光谱库…」，或者光谱库窗口里的「存入当前曲线…」，三处是同一个
对话框：

* **一条曲线一行**，中文名、英文名、样品号直接在表格里填。英文名填了认得的矿物名
  （Alunite），中文名自动补「明矾石」；反过来填「明矾石」补 Alunite。只补空着的或
  程序补过的格子，自己改过的不动。从库里加到图上的参照谱默认不勾——它本来就在库里；
* **分类在树上点一下**，不用记路径。上次放进哪个分类，这次默认还是它：野外一批样品
  往往都进同一个分类。没有合适的就「新建分类…」，建在选中的那个下面；也可以挂到
  随包库的分类底下（`mineral/silicate/我的补充`），树上照样写中文名；
* **兼属分类与蚀变组合**收在折叠区里。一种矿物本来就可能属于好几处——明矾石是硫酸盐，
  同时该出现在「高级泥化」里；自己采的样品既想按矿物归类，又想按矿区归。检索时主分类
  和兼属分类一视同仁；
* 岩性 / 描述、日期、备注这一批共用；**采样位置每条自动取自它在影像上的那个点**。

存的是**当前的 x / y 原值**，不含平滑、不含单位换算——那些是显示时的处理，存进库里
就退不回去了。

**导入。** 「导入…」认三种文件：

| 文件 | 怎么进来 |
| --- | --- |
| 文本表（.csv .txt .tsv …） | 第一列波长，其后每列一条谱。逗号、制表符、分号、空格分隔都行；表头之前的仪器说明行（ASD 导出那几行）自动跳过；没有表头就用文件名加序号起名 |
| ENVI 光谱库（.sli + .hdr） | 按头文件里的 wavelength、spectra names、reflectance scale factor 读；USGS 拿来当无效值的 -1.23e34 读成 NaN |
| .slb | 别人导出的、自己另一台电脑上的。原样并进来，分类、中文名、样品信息都在；同一条已经在库里的跳过，同一个文件并两次不会出两份 |

前两种读进来之后走上面那个「存入」对话框。读的时候做两件换算并在对话框顶上写明：
横轴最大值不到 30 的当微米、换成纳米；纵轴 95 分位超过 1.6 的不是小数反射率——90 上下
按百分数除以 100，几千上万按放大一万倍的整数除以 10000。阈值与编库时那道闸门一致：
库里每一条都得是 0~1 的小数，匹配才算得对。

**整理。** 把列表里的谱**拖到左边树上的分类里**：自己的谱是移过去，标准库的谱是复制
一份进来（带着中文名、化学式、样品号，来源记成它出自哪一套库）。右键也有「移动到
分类…」「复制到我的光谱…」。单条右键「编辑…」（F2）改名称、中文名、分类、样品号、
采样位置；选了好几条时「编辑…」就是一起移到另一个分类。Delete 删除，只删得了自己的。

**分类树上右键就能建分类**：在选中的节点下建子分类，或者直接建在「我的光谱」下。自己
建的能改名、能删；随包那些是编进库文件的，改不了。改名时底下的子分类和已经归进去的
谱一起跟着走；删只允许删空的——底下还挂着谱就拦住并说明原因，那是把东西弄丢的最快
方式。空分类单独记在个人库的 `folders` 里，不从条目反推：**分类是先建好、再往里放
东西的**，只从条目反推的话新建的空枝在树上根本不会出现。

**导出。** 「导出…」把选中的谱存成下面三种格式之一。**一行都不选就是当前条件下的
全部**：树上点「全部」、清空搜索框、来源选「全部」、取消「能盖住影像波段」，导出的就是
整个库（标准库连同自己的谱）。列表最多只列 2000 行，导出不受这个限制——没选中时按
当前条件重新检索一遍、不设上限。标准库的谱导出后仍挂在原来的分类下。整库导出实测：
.slb 约 40 MB、2 秒；ENVI 光谱库约 90 MB；CSV 约 200 MB（各套库的波长网格不同，宽表按
并集对齐，行数很多），整库分享用 .slb。

* **.slb**——发给别人，对方「导入」即可，分类与中文名全都带着；
* **ENVI 光谱库**——拿去 ENVI 里做 SAM 分类、波谱分析。ENVI 光谱库只有一条波长轴，
  取点数最多的那条谱的波长做轴，其余线性插值过去，超出各自测量范围的地方是 NaN
  （不外推）；
* **CSV**——第一列波长，其后每条谱一列，Excel、Origin 直接读。

**预览。** 列表里选中几条，底下就画出来（最多 8 条），横轴取谱的全部波段。只选一条
时曲线为红色，旁边列出这条谱的全部信息；选好几条时各用一种颜色，图上不画图例，旁边按
同样的颜色列出名字、样品号、粒度和波段范围，ASTER 同一矿物分粗中细、分短波和热红外的
几条由此分得开。不必先加到曲线图上才知道它长什么样。预览在页面里直接画成矢量小图，不走后端出图，
在列表里上下翻时不卡。

### 中文名

列表第一列是中文名，搜索框里直接搜「绿泥石」「赤铁矿」「层状硅酸盐」都行，名字正好
对上的排最前（不是按字母序排在前面的「黑云母-绿泥石」）。

随包库的名字全是英文，而且带着各家源库的习惯：`Alunite KAl`（后面跟半截化学式）、
`Albite (Feldspar)`、`AtacamiteCu`（化学式粘在名字后面）、`Ammonio-Jarosite`、
`Alun.33+Kaol.33+Musc.33`（混合物，带缩写和比例）。`names_cn.py` 先把名字收拾成干净的
词，再查表、拼词：

* **矿物**一个词对一个词查表，带化学前缀的拆开（`Na-Montmorillonite` → 钠蒙脱石）；
* **混合物**逐个成分翻，缩写有一张对照表（Kaol、Musc、Pyro……）：明矾石+高岭石+白云母；
* **岩石**按"修饰词在前、岩石名在后"拼：`Argillaceous Limestone` → 泥质灰岩，
  `Biotite Granite` → 黑云母花岗岩；矿物作修饰词时用习惯简称（角闪花岗岩、紫苏辉长岩），
  岩石名作修饰词时变成"质"（闪长质片麻岩）；玢岩、斑岩这类拼不对的整名对照。

**宁可没有，不能写错。** 查不着的词、拼不出来的名字一律留空，那一栏空着、英文名照常
显示。拿不准译名的十几个矿物（richterite、fassaite 之类）故意没收；岩石名里只要有一个
词不认得就整个放弃，半中半英的名字比没有更糟。植被、人工材料、有机物、陨石不译。现在
矿物条目 97.8% 有中文名，岩石 470/472。自己存的谱，中文名由自己填。

### 两种量纲画在同一张图上

影像里存的反射率多半是放大一万倍的整数，光谱库里存的是 0~1 的小数。**纵轴那个
下拉说的是"影像里的原值怎么读"，对库里的谱不适用**——拿一万去除它，0.4 的反射率
变成 0.00004，图上就是贴着坐标轴的一条直线。

所以每条曲线按**自己**的量纲换算：`Spectrum.native_unit` 记着这条谱本来是什么，
库里来的是 `"refl"`（已经是小数），影像上取的留空（按下拉换算）。轴要显示成百分数
时两者一起乘 100，要显示成小数时库里那条不动、影像那条除以一万。

「自动判断」那一档**只拿影像上那条去判**。库里的谱本来就是 0~1，拿它判等于什么都
没判——先在图上摆几条标样再去点影像，纵轴就会停在"反射率原值"上，影像那条几千的
DN 把纵轴一撑，三条标样全压成贴着底的直线。

横轴同理，但方向反过来：**自动范围由实测谱定，参照谱只是铺在上面**。库里那些
ASTER 标样一直测到 25 µm，跟着它把横轴撑开，影像那条 0.4~2.5 µm 的谱就被压进最
左边一指宽的地方。图上只有库谱时（纯翻库的情形）才按库谱取范围。

横轴范围里一条数据都没有时会自动退回全谱并在状态栏说一句。清空曲线也一并放回全
谱——范围是跟着当时图上那些曲线定的，曲线都没了，它就没有依据了。

### 曲线的三个手势

左键上挂着三件事，靠一道位移门槛分开：

* **悬停**——光标离哪条曲线最近（8 像素以内）就给它套一圈光晕，鼠标同时变成小手。
  没有这一下，"点曲线改颜色"就是个看不见的功能：图上没有任何迹象说明那条线可以点。
* **点击**——原地按下再松开，弹出取色器改这一条的颜色。

* **拖动**——按下之后**横向挪出 6 个像素**才开始，这时才画那条蓝带，松开缩放到
  那一段。双击回到全谱。

**读数、文件名这类长度不受控的文字一律用 `ElidedLabel`。** 普通 `QLabel` 的
`minimumSizeHint` 是"把全文一次放下"的宽度，布局照这个数把窗口撑开——鼠标在图上一
划，读数行写出「1000.0 nm  Kaolinite CM9 0.7603  Alunite HS295.1B 0.9243 …」，窗口
当场跳到一千三百像素宽，而且**再也拉不回来**：最小宽度被那行字钉住了。`ElidedLabel`
把 `minimumSizeHint` 压到 0、按可用宽度截断、全文留在 tooltip 里。（它的 `sizeHint`
必须按全文算，按截断后的算会自我收缩：文字短了宽度就小，宽度小了截得更短，几轮下来
只剩「100…」。）

浮标那一层（光晕、蓝带、参考线、读数框）画的时候要把 `figure.stale_callback` 摘
下来。往 Axes 上加 artist——哪怕转眼就删——会把图标成"脏"的，matplotlib 于是排一次
整幅重绘，那次重绘一到，刚贴上去的东西全被抹掉，人看到的就是闪一下什么都没有。
光把 `figure.stale` 按回去没用，重绘那时已经排上了队。

### 按类别取平均谱

「导入 → 按类别取平均谱…」。一句话：**选一个来源，勾几个类别，每类在这幅影像的
范围内把像元的光谱平均起来，一类一条曲线。**

三种来源：

| 来源 | 是什么 | 怎么分组 |
| --- | --- | --- |
| 样本库 | 当前工区里已经标好的样本点与图斑 | 按样本类别 |
| 分类栅格图层 | 单波段整数栅格，值是 0、1、2… 的类别号，背景是 nodata | 按类别号 |
| 矢量图层 | 带属性的矢量 | 按选定字段的取值 |

后两种正是端元提取结果的常见形态：端元位置栅格、或者把端元类型放在某个字段里的
矢量。把结果拖进画布当图层，这里就认得出来。

三者在 `samplelib/groupspec.py` 里被抹平成同一个接口：给一个类别，还一片布尔掩膜
和它在影像上的左上角行列号。取平均那一步谁都不用管，交给
`SpectrumReader.read_mask`。

**类别按树列，形状与样本树面板一致：工区 → 类别（可多级）→ 样本。** 工区那一层
不能省——同名类别分属两个工区时，拍平了就并排摆着、认不出谁是谁。工区节点自己不算
一条曲线，勾它等于把它下面的类别一起勾上；没填工区的归到「（未分组）」那一支，
与样本树面板的写法一致。

**默认只列落在影像里的。** 勾一个父节点等于把它下面的子类一起勾上。一个工区
几百个类别、影像只盖住其中几个，全铺出来等于让人自己去找哪几个有用——所以默认按
影像范围过滤，上面还有个搜索框。本身没有样本、只是为了让子类有处可挂的中间层也
留着，否则树会断在中间。

几处必须做对的地方：

* **一切统一到影像自己的像元网格上。** 平均谱是这幅影像上的读数，别处的网格再准也
  没用。矢量的几何先用 `to_pixel` 换成浮点行列号，再在**像元坐标系**里栅格化——给
  临时栅格一个单位仿射，GDAL 那边就完全不用知道投影是什么，也就没有第二次坐标变换
  带来的偏移。分类栅格则用 `gdal.Warp` 重采样到影像网格，只做两者重叠的那一块。
* **重采样一律最近邻。** 类别号插值出来的 1.5 不是任何一类。
* **按行分块，每块一次读全部波段。** 这一条是整件事的要害。逐波段读整幅看起来省
  内存，实际上对 **BIP 交错**的影像是灾难：一个波段的数据在文件里是每个像元一小段
  地散着的，读一个波段就要把整个文件扫一遍，读 166 个波段就是扫 166 遍。实测
  400 MB 的 BIP 影像，逐波段读 **13.4 秒**、按行分块读全波段 **0.1 秒**——快 134 倍，
  而且 BSQ、BIL 上也不比逐波段慢。第一版就是逐波段读的，在真实的 BIP 影像上表现为
  界面长时间无响应。
  掩膜里一行都没有的块直接跳过，一个小图斑在大影像上只读它自己那几块。
* **不抽样，所有像元都参与。** 既然一遍就能读完，抽样就没有必要了，结果是精确的。
  进度报到"第几块"那一层而不是"第几类"——一个类别铺满整幅影像时，光它自己就要读
  几百兆，只按类别报进度的话界面在那期间是死的，也按不了取消。
* **算不出来的类别不静静消失。** "一个像元都没落在影像上"和"算出来是这样"是两件完全
  不同的事——前者八成是坐标系或范围搞错了，对话框会把每一类的原因列出来。

曲线自动沿用类别的颜色（样本库类别、按唯一值赋色的矢量都自带颜色），图上的曲线与
画布上的图斑就对得上；不想要可以在对话框里关掉。

**分类栅格里的取值全部列出来，nodata 也在内，只是打个标签。** 文件里声明了 nodata
就先按它标上背景；**没声明就不替他猜**——二值图上 0 常常是背景，但 0 是个正经数字，
程序看不出来。右键「标为背景」自己指，标了只是默认不勾，真想看背景那一片的平均谱，
勾上照样算。（第一版是把 nodata 直接滤掉的，遇到没声明 nodata 的二值图就只剩一个
类别。）

分类栅格自动生成的类别名是**英文**（`Class 1`）——它要原样写到图例上。样本类别名、
矢量属性值是使用者自己的，多半是中文，图上得画得出来，见下面一节。

### 图上的中文

`font.sans-serif` 里排了几个中文字体**兜底**：拉丁字母永远落在 Arial 上，只有 Arial
里没有的汉字才轮到它们。两处必须做对，少一处就前功尽弃：

* **`font.family` 要写成显式的字体名列表，不能写 `"sans-serif"` 这个别名。**
  matplotlib 的逐字形回退（某个字在当前字体里没有就往后一个字体找）只在显式列表下
  生效；写别名时它只认 `font.sans-serif` 里第一个装了的字体，找不到汉字就画成空
  豆腐块。实测同一张图：写别名 5 条缺字警告，写显式列表 0 条。
* **列表要先按本机装了什么过一遍。** 名单里排中文兜底是为了跨平台（macOS 的
  PingFang、Windows 的微软雅黑、Linux 的思源黑体），到了具体一台机器上必然有几个
  是没有的；而显式列表下，matplotlib 每画一次文字就会为每个找不到的字体打一行
  `findfont: Font family 'X' not found`——一张图刷下来上千行。`installed_families()`
  过滤一遍并缓存结果。

### SG 平滑

取谱窗口底栏的「平滑」。Savitzky-Golay：在每个窗口里做一次最小二乘多项式拟合，取
拟合值当平滑结果。它比滑动平均好的地方正在于此——滑动平均会把峰压矮、把峰位往两边
推，而多项式拟合保留极值的高度与位置。判读吸收特征时，**峰深和峰位就是结论本身**。
实测 11 点二次拟合一个高斯峰，峰位不动、峰高保住 98.8%。

三处细节：

* **只影响显示与导出，原始数据不动。** 送去匹配的也是平滑后的那条——看到的是哪条
  曲线，比的就该是哪条，否则算出来的名次跟眼前的图对不上。
* **先挖水汽再平滑。** 反过来会把断口两侧的值顺着窗口搅到一起，等于凭空补出一段
  本来读不出来的谱。挖成 NaN 之后 `savgol` 是分段做的，短于窗口的段原样返回。
* **两端用第一个（最后一个）完整窗口的多项式在该位置上的取值**，与 scipy 的
  `mode="interp"` 一致。补零会把端点往下拽，镜像会在端点造出一个假的对称峰。

窗口长度必须是奇数（偶数没有中心点，SG 定义不成立），拨到偶数会自动往同方向再挪
一格。上限 51：再宽就把 2200 nm 那种几十纳米宽的吸收谷一起抹平了。

**两个数字框不跟着开关一起变灰。** 变灰的控件既看不出当前值有没有意义，也不给人
"调一下试试"的机会；手已经伸过去改数了，意思就是"我要平滑"，所以改了窗口或次数就
顺手把开关打开。

### 重新生成

改了 `MINERAL_CLASS`、`ALTERATION_GROUPS` 或者想换一套源库，改 `build_speclib.py`
顶上的配置再跑一遍：

```bash
python tools/build_speclib.py
```

它要 ENVI 的原始光谱库目录（`SRC_DIR`，默认指向仓库同级的 `光谱库/`，那份 63 MB
的源数据不入版本库）。跑一次几十秒。

源数据不在手边、只想在**已经编好**的库上做一次量纲体检与清理，跑另一个：

```bash
python tools/prune_speclib.py       # DRY_RUN = True 时只报告不改文件
```

它按同一条规则（`|y|` 的 95 分位 > 1.6）把整块剔掉，重算分类树条数，在 manifest
的 `pruned` 里留痕，改前存一份 `.bak`，改完再按使用者的读法复核一遍条数与量纲。

## 9. 样本标注

浏览模式的画布是只读的。要在图上画新样本、改已有样本的形状，点命令条最左的
**「标注」**（⌘2）切过去。

两种模式共用同一个画布、同一棵样本树、同一份图层栈，**画布状态在两者之间是共享
的**——视野、选中、「只显示勾选」都不会因为切模式而改动。区别只有三处：

| | 浏览 | 标注 |
| --- | --- | --- |
| 画布 | 只读，工具只有平移与选择 | 可编辑，六个绘制工具 |
| 数据源 | `SessionSource`（库内现状的只读投影） | `EditBuffer`（含未保存的暂存改动） |
| 命令条 | 库 / 导入 / 导出 | 六个工具 + 撤销重做 + 保存 |

**当前类别就是样本树上高亮的那一行**——不再有第二棵类别树。切到标注模式时如果
一条样本都没勾选，会自动改成"显示全部"（否则等于在白纸上画图），并在状态栏说明。
**这一下只在标注模式里算数**：回到浏览就还回去，也不写进会话状态。早先是一关
到底、还跟着存盘，于是浏览模式下样本树一条没勾、画布却把整库铺满，下次启动照旧
——开关在视图菜单里，使用者从没动过，根本无从知道是哪一步把它关掉的。使用者
自己在菜单里关的不受影响：不替他恢复，照常存盘。

### 图层

**加入图层有两种方式**：菜单「文件 → 添加影像 / 添加配准图片 / 添加参考矢量」，
或者**直接把文件拖进窗口**——拖到画布或图层面板上都行，可以一次拖多个。拖拽
按扩展名分派：

| 拖入的文件 | 处理 |
| --- | --- |
| `.dat .img .tif .bsq .bil .bip .hdr .vrt .jp2` … | 影像图层 |
| `.jpg .jpeg .png .bmp` | 配准图片图层（默认不透明度 0.75） |
| `.shp .geojson .gpkg .kml .gml .dxf .tab` … | 参考矢量图层 |
| 认不出扩展名 | 用 GDAL 依次试着当影像、当矢量打开——ENVI 裸数据文件常常没有扩展名 |

加载完会自动缩放到这批新图层的合并范围。加载失败的文件会逐个列出原因，不影响
同批其它文件。同一个文件重复加载是允许的（比如同一幅高光谱看两组波段），图层名
会自动加序号区分。ENVI 若点中 `.hdr`，会自动换成对应的数据文件。

| 类型 | 说明 |
| --- | --- |
| 影像 | GDAL 可读的任意影像（ENVI 高光谱、GeoTIFF…）。可选显示波段、拉伸分位数 |
| 配准图片 | 带世界文件或 ESRI 配准信息的 JPG / PNG |
| 参考矢量 | 只读对照用的矢量，可设颜色、填充、线宽，也可按属性唯一值赋色 |
| 样本 | 样本库自身，唯一可编辑的图层 |
| 底图 | 天地图（需自配密钥）、OpenStreetMap（无需密钥） |

**参考矢量按属性唯一值赋色**：图层面板右键「按属性唯一值赋色…」，选一个字段，
每个取值分到一个颜色，可以逐个改成规范要求的配色。配色表有 256 色
（`config.CLASS_PALETTE`：前 20 个是沿用至今的 tab20，其后按黄金角跳着取色相、
明度饱和度四档轮换——均分色轮的话相邻序号只差 1.4°，看着就是同一个颜色，而类别号
相邻的两类在图上往往也挨着）。地质图的岩性、地层代号都写在
属性里，整层一个颜色等于什么都读不出来。空值单列一类（显示为「（空值）」），不会
和空字符串混在一起。配色随会话状态一起记住。对话框里的**「按岩性图例」**会把取值
当岩性名去认，认出来的直接用标准岩性配色，见第 10 节。

**面填充的不透明度单独一条滑块**。矢量面默认半透明（好看清底下的影像），只拉图层
那条不透明度会一直觉得"拉到 100 了还是透的"——透的是填充，不是图层。两条相乘，
都拉满才是完全不透明。

**要素多的矢量走离屏缓存**。岩性图一帧要构造几十万个屏幕坐标点，全在 Python 里
做，一帧两三百毫秒；拖动时每次鼠标移动都重来一遍，手感就废了。超过
`VECTOR_CACHE_MIN_FEATURES`（默认 3000）个要素的图层因此先画进一张离屏图，之后每
帧只是把它贴上来，视图停稳后再重画一次——和影像图层用的是同一套缓存与同一个防抖
定时器。实测 8000 个图斑、710 万个节点的图：拖动中每帧从 235 ms 降到 1.7 ms，
停稳后一次性重画约 240 ms。另外两处优化一起生效：载入时建均匀网格索引（筛选从
几十毫秒降到零点几毫秒）、屏幕上不到 2 px 的图斑直接照外接矩形涂一小块。

**样本层同样走离屏缓存**（`SAMPLE_CACHE_MIN_FEATURES`，默认 3000，按数据源里的
样本总数算）。它与参考矢量的差别在于会被编辑，所以指纹分两截：**数据指纹**——数据
源的版本号（`EditBuffer` / `LibrarySession` 每改一次加一）、勾选集合、样式、正在拖
的顶点属于哪个要素——变了必须当帧重画，删掉的要素还贴在图上比慢更糟；**视图指纹**
（比例尺、投影）变了先拿旧图拉伸顶一帧，重画交给防抖定时器。平移两者都不变，只
是把图挪个位置贴。选中态的光晕、编辑手柄、正在画的草图仍逐帧直接画在缓存图之上。
实测 50000 个面：拖动中每帧从 190 ms 降到 1 ms，数据一变重画一次约 190 ms。

**影像与底图的重采样也留平移余量**（`RASTER_CACHE_MARGIN`，默认每侧 0.2）。原来
影像只按视窗大小重采样，一拖动，边上就露出一条画布底色，等 160 ms 防抖加一次
GDAL warp 才补上——有 GPU 的 Mac 上一闪就过，虚拟机里能看清楚地等它一下。现在往
外多画一圈：拖出去不到这一圈，只是把同一张位图挪个位置贴上，不重采样、边上也不
露空白；出圈或缩放才重采样。余量**只花还没花掉的预算**：视窗按设备像素算已经顶到
`ANNOTATE_RASTER_MAX_SIZE`（2600）的——Retina 上铺满屏幕就是——余量自动收到 0，
分辨率一个像素都不让，行为与从前相同；1x 屏、小窗口这类像素便宜的地方才留满，
代价是那一次重采样的像素面积近两倍。底图的取片上限按同一比例放大，层级与不留
余量时一样，只是多取周边几片（有磁盘缓存，平移过去本来也要取）。另外拖动 / 缩放
中贴图不再做双线性：位图被压到上限或正在缩放的那几帧，每帧都要把两千多像素宽的
图整个重采样，双线性比最近邻慢两三倍；停稳 180 ms 后补一帧平滑的。

**带颜色表的影像按颜色表显示**。分类结果、地质图这类 tif 把类别号存成单波段
索引，颜色在 GDAL 的 ColorTable 里；不查这张表就只能按数值拉伸，十几个岩性出来
是一片深浅相近的灰。这类影像加载时自动按颜色表出图，重采样一律用最近邻——类别号
是标称值，插值会插出本不存在的类别。图层属性里可以关掉，退回按数值拉伸看原始值。

每个图层都可独立调整**不透明度**，
可显隐、可拖拽排序、可缩放到图层范围。

**配准图片的坐标嗅探**：ArcGIS 导出的配准结果，世界文件常写成 `.jgwx`
（GDAL 只认 `.jgw` / `.jpgw` / `.wld`），坐标系则埋在 `.aux.xml` 的 `xml:ESRI`
段里（GDAL 只读标准的 `<SRS>` 节点）。这种文件直接 `gdal.Open` 会得到单位阵
地理变换和空坐标系——看上去打开了，位置全是错的。`annotate/georef.py` 会把
这些散落的信息补齐（世界文件候选后缀、ESRI aux.xml、`.prj`），并按四角计算
范围以正确处理带旋转的仿射。

**高光谱波长**：影像头文件没有 `wavelength` 时，会在 `WAVELENGTH_DIRS`
（默认含上级项目的 `assets/`）里找波段数吻合的传感器波长表（ZY1E / ZY1F /
GF5）供选择，波段数对不上的一律拒绝套用。

**底图**共 12 个，菜单里按服务商分节：

| 分组 | 图层 | 密钥 |
| --- | --- | --- |
| 天地图 | 影像、影像注记、矢量、矢量注记、地形 | `TIANDITU_KEY` |
| Mapbox | 卫星影像、卫星+路网、户外地形、街道、浅色、深色 | `MAPBOX_TOKEN` |
| 其它 | OpenStreetMap | 不需要 |

天地图走 `TILEMATRIXSET=c` 的经纬度切片（EPSG:4490），与样本库的存储坐标系
一致，**不需要重投影**；Mapbox 是 Web 墨卡托（EPSG:3857），拼好后经 `gdal.Warp`
重投影到 EPSG:4326。重投影的正确性用互相关验证过：两家的卫星影像在同一范围
渲染后，互相关峰值落在零偏移（dy=-1, dx=0 像元，约 43 m），而人为错开 8 像元
后相关系数从 0.518 降到 0.211。

缺哪把钥匙，就只有对应那组图层置灰，其余不受影响。瓦片带磁盘缓存（命中后整屏重渲染约 6 ms），单次视窗取片
数有上限（`TILE_MAX_PER_VIEW`），失败的片过 `TILE_RETRY_AFTER` 秒后允许重试。

缓存总量超过 `TILE_CACHE_LIMIT_MB`（默认 512 MB）时，按最后访问时间淘汰最旧的
片，一次清到上限的八成。命中会刷新访问时间，常看的区域不会因为下载得早就被
清掉。查总量要遍历上万个小文件，因此不是每写一片查一次，而是累计写入 8 MB
才查一次。

注记层（天地图的影像注记 / 矢量注记）大面积透明，会自动叠在其它底图之上。

#### 密钥怎么配

密钥不写在代码里，也不随包发。它们是账号凭据：写进源码就意味着随仓库外泄、随
每一份打包产物发给每一个客户、想换一次得重新发版。

按这个顺序找，一个都找不到就让相关底图在菜单里停用：

1. 环境变量 `TIANDITU_KEY` / `MAPBOX_TOKEN`；
2. 密钥文件 `<数据目录>/keys.json`，形如 `{"MAPBOX_TOKEN": "pk...."}`；
3. 都没有 → 空。

数据目录源码运行时是 `LithoSpectra-Studio/`（`keys.json` 已在 `.gitignore` 里），
打包之后是使用者的数据目录（Windows 为 exe 旁的 `userdata\`，macOS 为 `~/Documents/LithoSpectra/`）。
文件写出来时权限收成 `0600`。

界面上的入口是**底图菜单最下面的「配置底图密钥…」**：填一次立刻生效，菜单当场
重建，刚配好的那几个底图就能点了。打包产物里没有源码也没有配置文件可改，这是
唯一的填写方式；环境变量给的那个在对话框里只读地显示出来，注明改这儿不生效。

分发出去的产物**不带任何人的密钥**，每台机器各填各的。这也意味着新装的人第一次
打开时天地图与 Mapbox 是灰的——这是预期行为，不是缺陷。

### 标注流程

1. 在左侧样本树里选中要标注的**类别**——高亮的那一行就是当前类别；
   没有合适的就右键「在此工区下新建类别…」；
2. 点命令条最左的「标注」切到标注模式（⌘2）；
3. 选工具开始标注（工具只显示图标，数字键直达，悬停看全名）：

| 工具 | 快捷键 | 操作 |
| --- | --- | --- |
| 平移 | 1 | 拖动平移，滚轮缩放，双击全图；不拖动的单击等于点选 |
| 选择 | 2 | 单击选中，Shift 加选，拖框多选 |
| 画点 | 3 | 单击落一个点样本 |
| 画面 | 4 | 依次单击落点，双击 / 右键 / 回车闭合，退格删上一个点，Esc 放弃 |
| 改顶点 | 5 | 单击选中面，拖方块移动顶点，Alt 单击删顶点，单击边中点插入顶点 |
| 删要素 | 6 | 单击要素将其删除 |

选中的要素按 **Delete** 删除（macOS 上就是键盘上那颗 delete）。正在画图形时这颗键
先当"删掉上一个顶点"，画完了才轮到删要素。

画面时会自动**捕捉**到附近图斑的顶点（视图 → 捕捉顶点 可关），让相邻图斑严丝合缝。

**点样本既不捕捉、也不被捕捉。** 捕捉解决的是"两个图斑之间不能有缝"，那是边界
共用顶点的事；点样本是一次独立的观测，谁也不该跟谁重合。早先它两头都算：落一个
点样本时只要捕捉半径内有旧点就被吸过去，同一个位置于是叠上好几条坐标完全相同的
记录；而且画点时鼠标移动本来就不给捕捉提示（只有画面与画范围才给），落点却在背后
被吸走，最难察觉。现在画点就落在鼠标那儿，图斑的角也不会吸到点样本上。

### 一次点击落在哪，什么时候不算点击

「连着快点标注，有些点画不上去」的根子是**位移阈值被用在了不需要它的地方**：一次
点击从按下到松开隔着几十毫秒，手已经在往下一个位置挪。

平移要把"拖画布"与"点选"分开，选择要把"拖框"与"点选"分开，改顶点要把"拖顶点"
与"重选面"分开——这三处按下到松开 6 像素以内算单击。

画点、画面、画范围这几个工具**没有左键拖动手势**，阈值在这里只会把好好的点击判成
拖动扔掉。所以它们的落点容差放宽到 32 像素，快点也不会丢点。

在画点工具下想拖画布会落下一个点，⌘Z 就退回去了（真要平移：按住空格、用中键，
或切回平移工具）。

### 整理类别

类别的增删改全在**样本树的右键菜单**里，两种模式下都能用：

* **在此类下新建类别… / 在此工区下新建类别…**：建一个能往里画样本的类别。
  「新建分组」建的是只作层级容器、自身不存样本的节点，两者不同。
* **设置颜色…**：类别在画布上的显示颜色。
* **把勾选的 N 个类别合并到本类…**：先在树上勾选要合并的几个类，再右键目标类别。
  被并掉的类别**整支**（含它下面每一级子类别）的样本全部改归到目标名下，然后
  那些类别一起删除。目标的上级不算源——勾了父类别再右键它的一个子类，是把其余
  兄弟并进这个子类，父类别留下当容器；要把一支并进它自己的子类会被拒绝。合并
  只占**一个**撤销条目——使用者眼里它是一步操作，撤销时也该一次退回去。撤销会
  把类别连同**原来的 class_id、层级、attrs 与 origin** 一起放回来，样本按原属各
  归各位。因为撤得回来，这一步不再弹确认框。
* **撤销「新建类别 / 新建分组」**：类别里已经有了样本或子类别时拒绝撤销并说明——
  那些样本不在撤销栈里，跟着类别一起删就找不回来了。要删请用「删除该类别及其
  样本」。
* **删除该类别及其样本…**：连同子类与名下要素一起删。
* **删除该工区及其全部类别与样本…**（右键工区节点）：工区不是独立的表，只是类别
  上的一个字段，删工区就是把这个工区下每一级类别连同样本一起删掉，整批一个事务。
  与删类别一样会先确认并提示备份，撤销栈救不回来。

树在每次改动后都会整棵重建，**展开状态跟着一起还原**：重建前把展开的节点记下来，
重建后逐层展开回去（类别节点是懒加载的，展开一个还得跟着填它的子节点，否则下一层
就对不上）。工区节点从前有一句无条件的 `setExpanded(True)`，于是"在某个工区里新建
一个类别"看起来就像整棵树被重置——收好的工区一个不剩地全摊开了。现在工区也沿用
使用者上一次的选择，只有这一轮才冒出来的工区（含第一次建树）才默认展开。

### 暂存与落库

标注过程中的几何增删改**先暂存在内存里**，命令条右侧用陶土色实时显示未保存摘要。这样拖顶点不会反复写盘，撤销栈也保持一次操作一条记录。
确认无误后点「保存到样本库」才一次性写入 `.gpkg`。落库顺序是"先建类别 →
写要素 → 套用改动 → 最后删除"：类别的删除必须排在改归类之后，否则合并类别时
要素会跟着源类别一起被删掉。
**凡是会换掉当前库的动作——关窗、关闭样本库、打开另一个库、新建库、把 .gpkg
拖进窗口、重新载入——只要缓冲区里还有未保存的改动，都先问一句：先保存再继续 /
不保存丢弃 / 取消。** 早先「打开」「新建」「拖入」这三处不问，直接把缓冲区扔掉：
标注了半天、切到别的库看一眼，回来什么都没了，而且没有任何提示。丢样本的路径
一条都不能留。同一个库再"打开"一次不算换库，什么都不问、也不重载。

### 样本库文件

命令条右上角的库名是个按钮，点开就是这个文件的几件事：完整路径（太长时中间打省略
号，全文在悬停提示里）、**在访达中显示**（Windows 上是"在资源管理器中显示"）、复制
路径、另存为、备份到、从备份还原。同名的 `.gpkg` 常常有好几份（项目目录、
`Documents/LithoSpectra`、桌面…），只看文件名分不清现在开的是哪一份，所以这几件事
放在库名上——人看着库名想"这文件在哪 / 我要备份它"，手就在那儿。同样几条也在
「文件」菜单和命令条「打开样本库」旁的下拉里。

* **在访达中显示**：直接打开所在文件夹并选中这个文件，不弹框。
* **另存为…**（⇧⌘S）：整库复制到你选的位置，然后打开新的那一份，原文件不动。
* **备份到…**：整库复制一份到你选的文件夹，当前打开的仍是原来那一份。文件名默认
  「库名_备份_日期时间.gpkg」，默认放在上一次备份到的文件夹——备份通常是往同一个
  地方（移动硬盘、网盘同步目录）一份份地存。
* **从备份还原…**：列出样本库旁边 `backups/` 里的自动快照；自己备份到别处的，点
  「从其他文件还原…」去挑，会先核实它是样本库、写明两边各多少类多少条再确认。
* **最近打开**：用过的十个样本库，当前这个不重复列。

另存与备份都是"先拷到临时文件、只读打开核对类别与样本数、对上了才改名成目标文件"：
拷到一半出错，目标位置上原有的文件不会被半截的副本顶掉。做完不弹框，状态栏一句话
写明位置与核对结果，后面跟一个「在访达中显示」的链接——位置是你自己挑的，不需要
再弹框告诉你它在哪儿。标注模式下还有未保存的改动时先问：先保存再备份 / 只要已保存
的内容 / 取消——复制的是库文件，缓冲区里的草稿不在文件里。

### 什么时候才弹框

弹一个框，就是要使用者停下手上的事、读一句话、再点一下。这笔开销只有在**他真的
要做决定**时才值得付。据此定一条规则：

* **撤得回来的，不弹。** 保存（只含新增与改动）、合并类别、删除画布上选中的要素
  ——这些一步就能退回去，问"确定吗"得到的回答永远是"确定"，那不是确认，是每次
  操作都要多点一下的税。做完在状态栏说一句就够了。
* **撤不回来的，拦一道。** 把删除写进 GeoPackage、删除类别及其样本、放弃全部未
  保存改动、关窗时丢弃改动、恢复全部类别——这几处保留确认，并把备份怎么做写在
  框里，不是只喊一句"请先备份"。
* **做完了不再报喜。** 保存完成、恢复完成一律进状态栏。长任务的结果（导入、导出、
  裁剪的统计）仍然弹，那是真要看的数字。
* **"这一步没什么可做"的，不弹。** 没选中样本、还没有备份、库里还没有样本、
  重名工作区……这些进状态栏。
* **"为什么做不了"的，仍然弹。** 波段不够画不出曲线、没有波长表没法匹配、图层
  读不出来——使用者正等着结果，静悄悄什么都不发生比多一个框更难受。这类框还要
  顺带写清下一步该干什么。

**整个落库过程包在一个 GeoPackage 事务里，要么全成、要么全不成。** 中途任何一步
出错，前面已经写下的新类别、新要素统统回滚，暂存区仍是"未保存"状态，改完直接
重试即可。没有事务的话，半途失败会在库里留下一批已经落库的新类别，而暂存区并
不知情，重试就再建一遍同名类别——堆出一批重复且没有要素的空类别，事后很难分辨
该删哪一个。

**面要素的多部件结构在编辑往返中不会走样。** 库里的面样本存为 MultiPolygon，为
了让界面能按下标改顶点，读出来时所有环被拍平成一个列表，外环、内环、各部件混
在一起。写回去时按**几何包含关系**还原层次：被奇数层环套住的是孔，套住它的最内
层环是它的外环；被偶数层套住（含 0 层）的是独立部件的外环——孔里的岛同样成立。
这也正是 Shapefile 一贯的环解释方式。不这么做而按"第一个是外环、其余都是孔"，
两个互不相干的图斑会被写成"一个挖掉另一个"，面积归零、几何自交。

对既有样本的增删改一样走这套暂存：选中后 Delete 删除、用「改顶点」调形状、
「编辑 → 把选中要素改归到当前类别」换类别。

### 按画布上的选中集整理类别

标注时常有这样的情形：框选了一片要素，发现它们其实该单独成一类，或者归到别的
类去。在画布上**右键**（平移 / 选择工具下，指着要素或空白处都行）弹出的菜单里：

* **用选中要素新建类别…**：起个名字，新建一个基础类别，把选中的要素归进去。类别
  挂在这批要素原类别的同一级（来自不同类别时挂到工区顶层），几何种类由这批要素
  定。类别本身直接落库（与样本树上新建一致），要素的改归进标注缓冲区、保存时才
  写库——放弃改动，得到的是一个空类别，删掉即可。
* **把选中要素改归到其它类别…**：从列表里挑一个，不必先到样本树上选中它。列表只
  列装得下这批要素的基础类别（点归点类、面归面类、空类别都行），不列分组，也不列
  它们眼下所在的那个类。
* **把选中要素改归到当前类别**：归到样本树上高亮的那一类，原来就有。

右键落在一个**没选中**的要素上，先把它选成唯一选中再弹菜单——菜单里的动作全是对
选中集做的，指着一个、动的却是另一批，谁都会误操作；落在已选中的要素或空白处则
保留现有选中，框选一批再右键才成立。右键拖动仍是平移，正在画面时右键仍是闭合。
选中集点面都有时，上面几条都拒绝并说明：一个类别只装一种几何，分开处理。

## 10. 岩性图例库

一张「岩性名称 -> 标准岩性类 -> 颜色 + 花纹号」的对照表，放在
`samplelib/data/lithology_legend.json`，由 `tools/build_legend_library.py` 生成。
目前的用途是唯一值赋色对话框里的「按岩性图例」按钮；按属性导入时自动识岩性、
自动配色，接的也是这套接口。

### 数据来源与许可

| 来源 | 许可 | 提供什么 |
| --- | --- | --- |
| [IUGS-CGI SimpleLithology](https://github.com/CGI-IUGS/cgi-vocabs) | CC-BY 4.0 | 265 个岩性概念、`skos:broader` 层级、英文定义、100 个概念的中文标签 |
| [Macrostrat lithologies](https://macrostrat.org/api/defs/lithologies) | CC-BY 4.0 | 颜色与 FGDC-STD-013-2006 花纹编号 |
| [Macrostrat / ICS 国际年代地层表](https://macrostrat.org/api/defs/intervals) | CC-BY 4.0 | 102 个年代区间的官方配色（CGMW 色标） |

选 CGI 当骨架是因为它是国际地科联下属机构维护的受控词表，GeoSciML 与 INSPIRE
都用它，拿概念 id 作主键最稳；Macrostrat 的岩性名沿用英文习惯叫法，与 CGI 对齐
后有 233 个能直接取到颜色，其余顺着 `broader` 往上找最近的有色祖先（"斑状二长
花岗岩"本来就该长得像花岗岩），只有 7 个落到三大类的兜底色。

> **GB/T 958-2015《区域地质图图例》与 DZ/T 0179-1997《地质图用色标准及色标》没有
> 公开的机器可读版本，也不能在这里复制它们的色值**，因此本图例库不含国标配色。
> 要严格按国标出图，把标准整理成 `{岩性id: {"color": ..., "pattern": ...}}` 填进
> `build_legend_library.py` 的 `GBT958_OVERRIDE`，重新生成即可——名称匹配与层级
> 继承那套逻辑都不用动。花纹目前只记 FGDC 编号，没有内置花纹位图。

### 中文名从哪来

CGI 自带的中文标签只覆盖 100 个概念，而且缺的正好是中国区调最常用的那些，个别还
明显不对（phyllite 标成"粒硬绿泥石"、sand 标成"砂岩"）。生成脚本里的
`ZH_SUPPLEMENT` 按《岩石学》与区调报告的通用叫法补了一份，**补充表优先**，凡是它
已经占用的名字，词表那边一律让路。合计 146 个概念有中文名，其中 145 个拿到了真实
配色。CGI 里没有对应概念的（辉绿岩、糜棱岩、金伯利岩…）挂到语义上最接近的上位
概念——宁可粗一级，也不要错一类。

### 匹配规则

属性值是人写出来的自然语言，不可能指望它等于标准名。按可信度从高到低，命中即止：

| 规则 | 说明 | 例子 |
| --- | --- | --- |
| 完全一致 | 整串等于某个岩性名或别名 | `灰岩` → 灰岩 |
| 剥修饰词后一致 | 剥掉颜色、粒度、结构、成分前缀、蚀变等限定词再比 | `灰色中细粒黑云母二长花岗岩` → 二长花岗岩 |
| 以该岩性名结尾 | 中文岩石名是偏正结构、中心词在后，取能匹配的**最长**后缀 | `含砾粗砂岩` → 砂岩 |
| 名称中含该岩性名 | 中心词不在末尾时兜底 | `灰岩夹页岩` → 页岩 |

比较前先做归一化：全角转半角、去掉括号内容、去掉 `J2b ` 这类地层代号前缀、去掉
空白与标点、英文转小写。剥修饰词时每剥掉一个就重头再来，不能接着往下扫——剥完
"中细粒"若继续往后扫，"黑云母"的位置已经走过，轮到更短的"黑云"就把它咬掉一半，
剩一个孤零零的"母"字。

**认不出来就返回空，退回自动配色，绝不硬套**——一个错的标准色比一个随机色更容易
误导人。对话框里认出来的行会标上 `→ 匹配名`，鼠标停上去能看到它被归到了哪一支，
方便逐条复核；手动改过颜色的行不再显示推断结果。

同一个颜色被多个取值占用时自动错开明度（同类的"石英砂岩"和"长石砂岩"，以及本来
就共用一个色值的花岗岩与二长花岗岩）——图例上两行一模一样的颜色等于没分类，错开
之后仍在同一个色系里。

### 重新生成

```bash
python tools/build_legend_library.py
```

源数据缓存在 `tools/_legend_cache/`（已在 .gitignore 里），删掉即强制重新下载。

## 11. 长任务的进度与取消

导入、导出、按感兴趣区筛选都是长耗时 I/O。这些操作会弹出**窗口模态的进度框**，
带取消按钮，中途可以停下：

* 导入目录 / 根目录：停在当前文件，已导入的保留，报告注明还剩几个没导
* 按属性导入：第一遍扫描就取消的话一条都不写库，空手而归比写进去一半干净
* 导出：停在当前类别，不做覆盖校验（也不清理"遗留"文件——那些很可能还是上一次
  的有效结果），报告注明已取消
* 按范围选择：保留已经命中的部分

**长任务跑在后台线程里，独占样本库。** GDAL 数据集不是线程安全的，所有碰样本库
的接口共用一把锁，任务线程整段持锁——跑任务期间别的接口只能排队；只有查进度、
按取消这两个接口不拿锁。进度框是模态的，不会有人在导入进行到一半时又去点导出。
实现在 `webapi/tasks.py`。

**只动类别的操作不再全量重读。** 改名、改类别号、改说明、调整顺序这些一条样本
都没动，走 `LibrarySession.reload_classes()` 只重读类别表；两万条点样本上原先光
是改个类别名就要零点几秒，十万级会明显卡顿。动到样本归属或数量的操作（导入、
删除、合并、撤销）仍然走完整的 `reload()`。

**按属性导入的分级预览带缓存。** 界面上每勾一次分级字段就要把整个矢量文件扫一
遍，来回勾选是常态。结果按 `(文件, 修改时间, 字段组合)` 记住，勾回去是瞬时的；
文件在外部被改过，修改时间一变缓存自然失效。

**样本表的 `class_id` 建了普通索引。** 样本表原先只有空间索引，而按类别取样本
（导出、裁剪、统计都在做）走的是 `class_id` 上的等值 / IN 查询。索引是幂等的，
老库打开即自动补上。

## 12. 界面外观

完整规范在 `design-system/lithospectra/CLAUDE-STYLE.md`，令牌在
`web/src/generated/tokens.ts`。界面代码只引用语义令牌（`text`、`surface`、`primary`…），
不写死颜色值。

**暖象牙底 + 近黑墨色 + 单一陶土强调，硬边、无阴影。** 这不是审美偏好，
是功能判断：早先的主色是 `#1E40AF` 蓝，而岩性类别配色与岩性图例库里蓝色系占相当
比重，**界面 chrome 与数据在争同一段色相**，读图时要多一层辨认。现在 `primary`
就是墨色 `#141413`，整条色相带让给数据。

三条硬性约束：

* **色彩预算**：chrome 里的彩色像素不超过 2%。陶土 `accent` 只许出现在主 CTA、
  「未保存」标记、当前激活的绘制工具下划线、进度条填充这四处。类别色、图层色、
  图例色不在此限——那是数据。
* **激活态用下划线不用填充**：填一块彩底就等于往 chrome 里塞颜色。
* **圆角克制**：控件 6px、列表与卡片 8px、浮窗 10px、弹窗 12px。层级差异靠底色
  深浅与 1px 发丝线表达，全局无阴影。

菜单「视图 → 外观」可在 跟随系统 / 浅色 / 深色 之间切换。画布本身在两套主题下
都是深色——看影像必须如此。象牙 chrome 包着墨色画布，明暗节奏由此而来。

`display` 级、且位于深色面上的文字用衬线（画布空状态、关于窗口）。中文衬线要 22px 以上才立得住，低于这个字号一律不用。

**对比度是算出来的，不是看出来的**。23 组必须达标的前景/背景配对，正文按 WCAG 的
4.5:1、非文字界面元素按 3:1 逐项验算，两套主题共 46 项。

历次查出的问题都不是调一下数值就完事的：

* 占位文字与禁用文字原本共用一个颜色。占位文字承载信息、要满足 4.5:1，而禁用
  控件被 WCAG 1.4.3 明确豁免、本就该淡；共用一个值必然有一头不对，于是拆成
  `text_placeholder` 与 `text_disabled` 两个令牌。
* 控件描边只有 1.48:1。WCAG 1.4.11 要求「用于识别控件的视觉边界」达 3:1，输入框
  描边属于此列。
* **画布上的"选中"标记不能用 `primary`**。画布在两套主题下都是深色，而浅色主题
  的 `primary` 是近黑墨色，框选矩形与选中光晕实测只有 **1.05:1**——黑底上画黑线，
  等于什么都没画。为此单列了 `canvas_select` 令牌（15.6:1），并改成"先压一圈暗的、
  再描一圈亮的"双描边，落在任何颜色的图斑上都看得见。
* 深色主题的焦点环用陶土而不是象牙：象牙与 `text` 同色，焦点环落在文字旁边会跟
  文字混成一片。

结构性分隔线（面板之间的细线）不在校验之列并写明了理由：它是装饰，不承担识别
控件的职责，硬套 3:1 会让整个界面布满深色格线。

图标是内联的矢量描边图形（24×24 网格、统一 1.6px 描边），按主题色现场渲染。
界面里不出现 emoji：emoji 的字形由系统字体决定，跨平台长得不一样，也没法跟着
主题换色。

### 为什么只有一个窗口

早先是主窗口 + 标注窗口两个。清点下来，**八样东西在两个窗口里各实现了一遍**：
类别树、图层面板、底图菜单、撤销、缩放、备份、帮助、画布。两窗口合计 61 个常驻
可点控件，其中约三分之一是这种重复。

合并之后按钮不是"砍掉"的，是结构性消失的：

| | 合并前 | 现在 |
| --- | --- | --- |
| 窗口 | 2 | 1 |
| 顶级菜单 | 8 + 5 | 4（文件 / 编辑 / 视图 / 帮助） |
| 常驻面板 | 5 | 2（左：样本树 + 图层清单；右：检查器 + 要素信息） |
| 命令条控件 | 12 / 10 | 7（浏览）· 12（标注） |
| 面板常驻按钮·滑块·下拉 | 35 | ≤4，随选择变 |
| **任一时刻可见的可点控件** | **27 / 34** | **14 / 19** |

三个结构性动作：

* **模式取代窗口**。命令条最左是「浏览 | 标注」二段控件（⌘1 / ⌘2）。
* **四个面板并成一个检查器**。右栏按当前选中什么切内容：没选中是库概览与
  选中类别 / 样本 / 图层就显示各自的属性。
* **面板底部那两排按钮全删**。新建、改名、合并、删除、上移、下移、缩放、移除
  本来就全在右键菜单里，按钮只是第二条路径。删掉之后右键菜单成为唯一路径，
  因此它**必须键盘可达**——`Shift+F10` 与 `Menu` 键。

### 感兴趣区就是一个图层

早先的感兴趣区是"藏在会话里的一个隐形范围"——导入之后看不见、改不了、也导不出，
过一会儿就不知道它还在不在。现在它是**普通图层**：

* 命令条上的**「画范围」**工具（两种模式都能用）在图上圈一块，落进「感兴趣区」
  图层。按钮右侧的下拉选形状：

  | 形状 | 画法 |
  | --- | --- |
  | 多边形 | 依次单击落点，双击 / 右键 / 回车闭合 |
  | 矩形 | 按住拖出对角线 |
  | 圆（从中心拖） | 在圆心按下，拖到需要的半径松手 |

  矩形与圆都在屏幕坐标里算好再逐点换算成经纬度，因此屏幕上是正圆正矩形，
  换到经纬度自然成了椭圆与梯形——等距圆柱投影下同一段地面距离在经度方向
  本来就占更多度数。圆以**按下点为圆心**而不是外接矩形定圆：想圈的往往是
  "以这个露头为中心方圆多少"，中心的位置是确定的，边界不是。
* 图层清单里看得见它，能改颜色、调透明度、关掉、缩放过去。
* 右键 →「**用该图层范围选择样本…**」按它筛样本。任何有要素的矢量图层都能这么
  用，不限于手绘的。筛选方式（相交 / 完全包含 / 中心点在内）、"只在检索匹配的类别
  里筛"、"追加到现有选择"这三个参数在**动作发生时问一次**。它们原来常驻在检查器的
  「感兴趣区」那一块里，那是改成图层之前的入口；入口挪走之后那一块就剩三个悬空的
  控件和一行"未导入感兴趣区"，功能早就不从那里走了，界面上却一直摆着——已经删掉。
  参数跟着动作走，比常驻在一个跟它无关的面板上清楚。
* **影像图层右键 →「生成范围图层…」**，把它的覆盖范围变成一个范围图层。会先问
  按哪种范围：

  | | 用在什么时候 |
  | --- | --- |
  | 有效数据轮廓 | 影像是斜的、有黑边。按 nodata 掩膜勾出实际覆盖的地方 |
  | 四至矩形 | 正射好的规则影像，四角就是范围，快 |

  斜条带影像的四至会把大片黑边圈进来，用它筛样本会选中一堆压根没有影像覆盖
  的点——而"这批样本在这景影像上裁得出块吗"正是要问的问题。掩膜矢量化前会
  降采样到长边 1024 以内（`roi.MASK_MAX_SIDE`），一景两千万像元的影像也就是
  一两秒，边界误差最多一个降采样后的像元。

  **生成的是图层而不是直接筛掉。** 范围一旦是图层，就能先看一眼对不对、改颜色、
  跟别的范围叠着比、导出给别人，想筛再右键筛。直接筛掉的话这些都没了，筛错了
  还得把矢量化重跑一遍。互不相连的几块（云掩膜、拼接缝）会拆成一块一个要素。
* 右键 →「**导出该范围为矢量…**」写成 GeoJSON / Shapefile / GeoPackage。
* 编辑 →「**按图层范围选择样本…**」列出所有可用的图层让你挑。

筛选参数（相交 / 包含、是否只在检索结果里筛、是否追加到现有选择）在右栏检查器
的「库概览」页——没选中任何东西时就是那一页。

从文件导入范围仍然可以（检查器里的「导入…」），它会同时把那个矢量铺成图层，
省得筛完了不知道范围长什么样。

### 新建工作区

样本树右键 → 「新建工作区…」，或 编辑 → 「新建工作区…」。

**工作区不是独立的表，只是类别上的一个字段**，所以空工作区留不住——新建时会
接着问"下面的第一个类别叫什么"，一并建出来。同理，把一个工作区里最后一个类别
删掉，这个工作区也就不存在了。

### 两套"选中"是两回事

| | 存在哪 | 干什么用 | 怎么改 |
| --- | --- | --- | --- |
| **勾选** | `session.selection` | 导出、裁剪的工作集；也是「只显示勾选的样本」过滤的依据 | 样本树上的复选框 |
| **画布选中** | 页面里的画布状态 | 当前要操作的要素：高亮、删除、改归类别、改顶点 | 画布上单击 / 框选 |

画布选中只能落在**画得出来**的样本上：「只显示勾选」
藏起来的、样本图层关掉的，点选、框选、右键、捕捉都碰不到；勾选变了，看不见的
那些自动移出画布选中。否则树上一个没勾、画布空空如也，框一下照样选中一批看不见
的样本，紧接着的「删除选中」「改归」动的全是屏幕上没有的东西。

两者**互不影响**。早先它们是同一个集合、双向同步，后果是在画布上框一下就把
辛苦勾好的一批冲掉，而「只显示勾选」会立刻把没框中的样本全藏起来——**框选反倒
什么都看不见**。

要把画布上框出来的一批并进勾选，用 编辑 →「把画布选中的加入勾选」。反过来
不会自动发生。

画布选中用**双描边光晕**标出：先压一圈画布底色的粗线、再描一圈 `canvas_select`
的亮线，落在任何颜色的图斑上都看得见，「只显示勾选」开着时也照画。

### 草稿永远看得见

「只显示勾选」筛的是库里那上万条，**草稿（FID 为负）不在它管辖之内**。少了这条
豁免，标注就成了"画一个消失一个"：勾选非空时进标注模式过滤不会自动关掉
（只在一条都没勾时才关），于是每画一个点，它立刻被筛掉，
屏幕上只剩刚画的那一个——那还是选中光晕画出来的，不是样本层画的。

同一件事在保存那一刻还会再犯一次：草稿落库变成普通样本，仍然没被勾上，于是刚
存完就"标注全没了"。因此 `EditBuffer.commit()` 把新写入的主键一并返回，
保存时如果过滤开着，把这一批勾上，保存前后画布上看到的东西不变。
只在过滤真的开着时才动勾选集——否则平白改了使用者攒好的导出工作集。

窗口窄于 1280 时右栏自动收起；使用者手动关过之后，窗口再变宽也不会替他做主。

## 13. 编辑与恢复

样本的几何自始至终不可编辑，可改的只有分类结构与名称，因此任何操作都不会
动到样本本身。在此之上还有三层回退保障：

| 层次 | 入口 | 作用 |
| --- | --- | --- |
| 逐步撤销 | 编辑 → 撤销（Ctrl+Z） | 回退本次会话的单步操作，保留最近 100 步 |
| 恢复初始分类 | 编辑 → 恢复全部类别到导入时的状态 | 依据 `sl_class.origin` 还原名称、类别号、工区、层级，删除新建的空分组，清空样本自定义名称 |
| 文件级备份 | 文件 → 备份到… / 从备份还原… | 整库回到任意一份备份 |

「备份到…」存到你选的位置（见第 9 节「样本库文件」）。程序自己只在一种情况下留
快照：还原之前，存在样本库同级的 `backups/` 里，命名为
`<库名>_<时间戳>_before-rollback.gpkg`（同一秒内再存一份自动加 `_2`）。复制完立刻
只读打开一遍核对类别与样本数，对不上就删掉副本报错——拷坏了的备份比没有备份更糟，
那时人以为自己有退路。

**除此之外没有任何自动备份**。备份什么时候做、做不做，由你决定：

* 「文件 → 备份到…」（或点命令条右上角的库名）存一份；
* 或者直接复制样本库文件本身。

会丢样本、撤销栈又回不来的操作——删除类别、整库恢复分类、标注落库里含删除的
部分——在执行前会弹一段提醒，把上面两条办法和样本库文件的真实路径一并写出来，
但**不替你动手**。

唯一的例外是「从备份还原」：它在覆盖之前必定先把当前状态另存一份
（`_before-rollback`），否则这一步本身就没法回退，那就不是备份而是陷阱了。

撤销"新建分组"时若分组下还挂着类别，会先把它们托管给上级再删除分组——
撤销操作不会连带删除任何样本。

### 功能模块

光谱、样本裁剪、预处理工具箱、在线底图、野外记录不属于底座，是按客户需求装或不装
的模块。一个模块一个目录，`module.json` 是它的身份：id、名称、版本、依赖的模块、
随模块走的数据文件。清单写坏了（不是 JSON、缺字段、目录名与 id 对不上）只跳过
那一个模块，程序照常起来。

装哪些由 `config.MODULE_PROFILE` 指的 profile 说了算：

| profile | 模块 |
| --- | --- |
| `full` | 在线底图 + 光谱 + 裁剪 + 工具箱 + 野外记录 + 深度学习 |
| `analysis` | 在线底图 + 光谱 |
| `basic` | 一个都不装，只有底座 |

后端只给装上的模块挂接口（`webapi/app.py`），模块的接口文件用到时才 import——
没装的模块目录不在包里，顶上 import 会让整个后端起不来。页面按 `/api/modules`
的结果决定显示哪些入口：没装的模块界面上没有入口，而不是灰掉一个点了报错的菜单项。

`packaging/LithoSpectraWeb.spec` 读同一份 profile 决定带哪些代码与数据。基础版里
光谱模块那 12.9 MB 的 `spectral_library.slb` 根本不进包。清单用 JSON 不用 YAML，
正是为了 spec 能在不 import samplelib 的前提下读它。

`tests/test_edition.py` 验的就是这一条，而且是真删：把 `samplelib` 与 `webapi`
复制到临时目录，按 profile 把不要的模块目录 `rmtree` 掉，再在干净的子进程里把
后端建起来，核对哪些接口在、哪些不在。

```
[basic]    只留底座        底座接口 81 个，没有光谱、裁剪、野外记录接口    samplelib 0.6 MB
[analysis] 留底图 + 光谱   底座 + 光谱共 111 个接口，没有裁剪接口         samplelib 13.8 MB
```

### 自测

```

python tests/run_all.py
```

## 15. 打包分发

### 构建

macOS：

```bash
conda activate samplelib
cd LithoSpectra-Studio
bash packaging/build_web_macos.sh
```

脚本先在 `web/` 下编译页面，再按 `LithoSpectraWeb.spec` 打包、裁剪、做两步冒烟
测试，最后压成 dmg。产物在 `packaging/dist-web/`：`LithoSpectraWeb.app` 与
`LithoSpectraWeb-arm64.dmg`。冒烟测试在临时家目录下进行，不碰构建机上已有的数据。

Windows：在资源管理器里双击 `packaging\build_windows.bat`，不需要开命令行，
**也不需要先建环境**。批处理自己找到 conda，`samplelib` 环境不存在就按
`environment.yml` 建一个，缺 pyinstaller 就现装，然后交给 `build_windows.py`：
查依赖 → 编译页面（没装 Node.js 时用已有的 `web\dist`）→ PyInstaller → 裁剪 →
**查包里有没有无关的库** → 两步冒烟测试 → 压 zip。产物在
`packaging\dist-win64\LithoSpectraWeb\`，同时压出 `LithoSpectraWeb-win64.zip`
供分发。完整流程与常见报错见 **[packaging/WINDOWS.md](packaging/WINDOWS.md)**。

两个平台用同一份 spec。窗口库 pywebview 每个平台只带一个后端：macOS 是 Cocoa +
WebKit，Windows 是 WinForms + Edge WebView2（经 pythonnet 调 .NET），其余后端与
另一平台专用的库（macOS 的 Vision 文字识别、Windows 的 pythonnet）都不进包。打包
必须在目标平台上做，PyInstaller 不能跨平台打包。

`packaging/` 下各文件的分工：

| 文件 | 作用 |
| --- | --- |
| `LithoSpectraWeb.spec` | PyInstaller 配置：入口 `entry_web.py`、带上 `web/dist`、随包数据、GDAL 驱动插件、排除清单、macOS 包信息 |
| `entry_web.py` | 打包入口，只调用 `webapi/desktop_app.py` 的 `main()` |
| `runtime_hook_gdal.py` | 启动时把 `GDAL_DATA` / `PROJ_LIB` / `GDAL_DRIVER_PATH` 指向包内数据 |
| `prune.py` | 打包后删掉 PyInstaller 多收的文件，每条都注明依据 |
| `build_web_macos.sh` | 编译页面 → 打包 → 裁剪 → 两步冒烟测试 → dmg |
| `build_windows.bat` | Windows：双击入口，负责找 conda、**没有环境就建一个**、补 pyinstaller、暂停窗口 |
| `build_windows.py` | Windows：查依赖 → 编译页面 → PyInstaller → 裁剪 → 查无关库 → 两步冒烟测试 → 压 zip |
| `WINDOWS.md` | Windows 从装 Miniconda 到产出 zip 的完整流程与常见报错 |

### 冒烟测试与自检

构建脚本打完包做两步：

1. **自检**。设环境变量 `LITHOSPECTRA_SELFTEST=<报告路径>` 启动产物，它不开界面，
   把该带的东西挨个点一遍，报告写成 JSON，全过退出码 0：GDAL 必备驱动
   （GPKG / GTiff / ENVI / Shapefile / GeoJSON / KML…）、`proj.db`（拿一个已知点
   做 EPSG:4326 → 3857 验数——proj.db 没带上时 PROJ 不报错，只是算错）、后端整套
   接口建得起来、编译好的页面与 pywebview 在包里、选中模块下**每个子模块**都
   import 一遍、matplotlib 真画一张图、图标与波长表、工具箱与去噪 Worker 的源码树
   在不在、野外记录的修补库在不在。
2. **真启动**，等窗口里的页面把界面状态写回后端（`state/web_session.json` 出现），
   确认页面确实连上了后端。

只看"进程活着"抓不到"起得来但少了东西"：矢量拖进去坐标飘了（proj.db）、`.jp2`
读不了（驱动插件没进包）、光谱一点就崩（排除清单排掉了 matplotlib 在 import 时
就要的 `unittest`）。这类缺失只在打包产物里发作，开发机的环境里什么都有。自检逻辑
在 `samplelib/selftest.py`，`webapi/desktop_app.py` 看到那个环境变量就转过去。
排障时可以对已经装到别人机器上的产物手工跑一遍：

```bash
LITHOSPECTRA_SELFTEST=/tmp/report.json  LithoSpectraWeb.app/Contents/MacOS/LithoSpectraWeb
```

### GDAL 驱动插件

conda-forge 从 GDAL 3.9 起把 JPEG2000（`libgdal-jp2openjpeg`）、HDF5、netCDF 这些
驱动拆成独立的插件包，装在 `lib/gdalplugins/`，`libgdal` 本体里没有。spec 把这个
目录整个当 `binaries` 带进包内 `gdal_plugins/`——登记成二进制而不是数据，
PyInstaller 才会顺着把插件自己链的 `libopenjp2` 等依赖一并收进来。运行时钩子把
`GDAL_DRIVER_PATH` **覆盖**（不是 `setdefault`）到那里：使用者 shell 里若残留着
别的 conda 环境设的这个变量，顺着它去装另一个版本 GDAL 的插件只会报"不兼容"。
包里没有插件目录时设成 `disable`，也不去碰系统上另一份 GDAL 的默认目录。

环境里装了哪些插件，产物就有哪些；自检报告里 `checks.gdal.jp2` 说的就是
JPEG2000 有没有跟上。

### 工具箱子进程

工具箱与去噪 Worker 跑在使用者自己选的解释器里，那多半是另一个 conda 环境。
本进程环境里指着自己那套 GDAL / PROJ 的变量——conda 激活时设的
`GDAL_DRIVER_PATH` / `GDAL_DATA` / `PROJ_DATA`，打包后是启动钩子指到包内那份的
——对子解释器全是错的路径，尤其 `GDAL_DRIVER_PATH` 会把它自己的插件目录顶掉，
JPEG2000 这类插件驱动就此消失。探测环境、启动批处理、启动 Worker 三处都先按
`toolbox.envs.ENV_LEAKS` 洗一遍再启动。

### 打包后数据放在哪

数据目录由 `samplelib/datadir.py` 决定：

| 运行方式 | 数据目录 |
| --- | --- |
| 源码运行 | `LithoSpectra-Studio/` |
| Windows 打包版 | exe 同级的 `userdata\`；exe 所在目录不可写时为 `%USERPROFILE%\Documents\LithoSpectra\` |
| macOS 打包版 | `~/Documents/LithoSpectra/`（.app 包内不能写入） |

设置环境变量 `LITHOSPECTRA_DATA_DIR` 时以它为准，打包脚本的冒烟测试用它把数据写到临时目录。

Windows 旧版本的数据在「文档\LithoSpectra」。新版首次启动且 `userdata\` 为空时，把旧目录的
内容移过去，并把 `state/`、`dl/` 下 JSON 与 NDJSON 文件中指向旧目录的路径改为新目录；瓦片缓存
与栅格缓存不移动。迁移结果写在 `state/last_run.log` 开头。

数据目录的结构（以 macOS 为例）：

```
~/Documents/LithoSpectra/
├── data/
│   ├── backups/                还原前自动留的快照
│   ├── tilecache/              底图瓦片缓存，超出上限自动淘汰，删掉即清空
│   ├── rastercache/            大影像的显示金字塔，删掉即清空、下次重建
│   └── models/                 野外记录去水印用的修补模型，用到时下载
├── dl/                         深度学习的任务、样本集登记与骨干插件
├── state/
│   ├── session.json            最近打开的样本库
│   └── web_session.json        界面状态：视野、勾选、图层、面板开关
├── my_spectra.slb              我的光谱
├── keys.json                   底图密钥
└── wavelengths/                自备的传感器波长表（.txt），需要时自己建
```

macOS 上家目录不可写时退到临时目录。GF5、ZY1E、ZY1F 三张波长表已随包携带；影像的 ENVI 头缺
`wavelength` 又不是这三种传感器时，把自己的表放进 `wavelengths/` 即可。

分发版不带样本库：首次启动打开空界面，由使用者新建或打开自己的库。spec 的
`SEED_LIBRARY` 指定一个 `.gpkg` 时，包内会带上它，首次启动复制到 `data/` 下。

随包只读资源集中在 `resources/` 下，代码通过 `config.RESOURCE_DIR` 与 `config.resource_path()`
定位。Windows 产物中它在 exe 同级，macOS 在 .app 包内：

```
resources/
├── assets/        图标、传感器波长表
├── spectra/       标准光谱库 spectral_library.slb、诊断特征 spectral_features.json
├── legend/        岩性图例 lithology_legend.json
├── toolbox/       预处理工具箱源码
├── workers/       去噪与深度学习 Worker 源码
└── seed/          初始样本库（spec 设置 SEED_LIBRARY 时才有）
```

### 会话状态

退出时记下界面的样子，下次启动摆回去：上次开的样本库、画布视野、勾选的样本、
检索词与树的展开、画布上叠的图层、面板开关。

记的是**怎么看**，不是数据本身：样本始终以样本库为准，图层引的是磁盘上原本就在
那儿的文件。文件坏了、版本对不上、里面引的图层文件没了，一律当作没有状态，界面
照常打开——一份图方便的文件不该成为进不去程序的理由。

把 `webapi/desktop_app.py` 的 `RESTORE_LAST_LIBRARY` 改成 `False`，启动时就不再
打开上次的样本库。删掉 `state/web_session.json` 则界面回到默认布局。

### 体积

GDAL 及其依赖约占一半，其余是 Python 运行时、numpy、matplotlib、h5py，以及野外
记录用的 onnxruntime 与 OpenCV。压下来靠三处：

- **不带无关的库**。窗口用系统自带的 WebView，Qt、Tk 都不进包；构建环境里装着的
  PyTorch、SciPy、scikit-image、pandas、Jupyter 等在排除清单里，pywebview 只带当前
  平台的那一个后端。Windows 的打包脚本最后还会扫一遍产物，带进了这些就判失败。
- **只打 arm64**。需要给 Intel Mac 分发时把 spec 里的 `MAC_TARGET_ARCH` 改掉重打。
- **裁剪**。`prune.py` 删掉 tkinter 的 Tcl/Tk 运行时、与 `gdal_data` 重复的一份
  GDAL 数据；Windows 上再删 OpenCV 的视频插件。

GDAL 的驱动没有裁。`samplelib` 常用的是 GPKG、Shapefile、GeoJSON、GTiff，
但拖拽入图层时会用 GDAL 依次试探未知格式，砍驱动会让这条路径悄悄失效。

### 签名

产物未做代码签名与公证。macOS 上对方首次打开需右键 → 打开，或在「系统设置 →
隐私与安全性」里放行；免除这一步需要 Apple 开发者账号，用 `codesign` 加
`notarytool` 走一遍。Windows 上 SmartScreen 首次拦截时点「更多信息 → 仍要运行」；
免除需要代码签名证书。

### 图标

macOS 用 `assets/logo.icns`，Windows 用 `assets/logo.ico`，界面内的窗口图标走
`assets/logo_256.png`。想换配色或形状，改 `tools/make_logo.py` 顶部的配置区
后重跑该脚本，所有尺寸会一并重新生成。

## 16. 野外记录

野外调查时拍的照片、走过的轨迹、落下的观察点，整理进同一个样本库里看、改、出图。
兼容奥维互动地图的收藏夹文件（`.ovobj`），之前用奥维记的东西直接导进来。只在 Web
界面版里有，命令条「野外」与菜单栏「野外」是入口；模块 id `fieldwork`，全功能版装。

**野外点位与岩性样本是两回事。** 样本是分好类、拿去训练与制图的成果；野外点位是现场
的观察记录——名称、描述、一组照片，测过光谱的还链着光谱库里的谱。两者存在同一个
`.gpkg` 里，但各占各的表，样本树、样本导出、样本裁剪都看不到野外点位。要把某个点位
用作样本，在点位详情里「复制为点样本」，选一个点类别显式复制，点位本身不动。

### 存储

| 表 | 内容 |
| --- | --- |
| `fw_point` | 野外点位（Point，EPSG:4326），名称、类型、备注、高程、自定义属性、所属批次 |
| `fw_track` | 轨迹（LineString ZM：Z 是高程，M 是 Unix 秒），长度、起止时间、高程范围 |
| `fw_photo` | 照片：挂在哪个点位、当前文件与原始文件、拍摄时间、位置、朝向、编辑记录 |
| `fw_spectrum` | 点位链接的光谱库条目 id |
| `fw_import` | 导入记录，同一份文件再导时提示 |

照片原图不进 gpkg，放在库文件旁边的 `<库名>.media/` 里，按内容的 SHA-256 命名，同一张
照片导两次只占一份。编辑照片（去水印、加水印、裁剪调色、框选修补）从不覆盖：结果另存
一份，照片记录指向新文件，原始文件一直在，随时「还原原图」。文件只增不改，所以备份
出去的库与原库共用同一个媒体文件夹也不会互相踩；备份副本找不到同名 `.media` 时，按库
里记下的原位置去找。

记录之间用 uid（文本）互相引用而不是 FID，为以后 iOS 端离线新建、回来合并留的口子。

### 导入

* **奥维收藏夹（.ovobj）**：标签成为点位，轨迹带着逐点时间与高程进来，内嵌照片原样
  存进媒体文件夹（EXIF 不动）。批次默认是文件名——奥维里通常一天一个文件。坐标按
  WGS84 读，文件里存的就是 WGS84，不做火星坐标偏移。点位按奥维对象 id 认人：同一份
  文件改过再导，已有点位按奥维里的最新名称、备注、位置更新，已有照片与轨迹跳过。
  没挂照片的点位，高程从同一时刻附近的轨迹点上取。
* **照片 / 照片文件夹**：读 EXIF 里的位置、时间、朝向。挂到哪个点位有四种：全部挂到
  指定点位；按 GPS 挂到一定距离内最近的点位（默认 30 m）；每张新建一个点位；先不挂。
* **GPX / KML / GeoJSON**：点要素成为点位，线要素成为轨迹。
* **拖进窗口**：`.ovobj`、照片、`.gpx` 归野外记录，其余照旧当图层加载。选中一个点位
  时拖进来的照片默认挂到它上面。

`.ovobj` 的格式奥维没有公开，解析器（`samplelib/modules/fieldwork/ovobj.py`）的文件头
注释写明了逐字节对出来的结构：对象块、附件块、轨迹坐标的差分位打包、时间与高程的
变长整数。用真实数据逐点核对过奥维自己导出的 GeoJSON。

### 面板与照片浏览器

「野外记录」浮动窗口左边按批次列出轨迹与点位（右键批次可改名），右边是选中项的详情：
点位的类型、备注、高程、自定义属性（岩性、产状、样品号……按需添加）、照片缩略图、
链接的光谱曲线；轨迹的时长、长度、高程剖面。照片缩略图拖动可以排序，拖到左边列表的
另一个点位上就改挂过去。画布上野外点位是带白边的菱形（样本是圆点），轨迹按批次着色，
选中点位时照片的拍摄朝向画成一个小三角。

点开照片进浏览器：滚轮缩放、拖动平移、双击放大或回到全图，← → 翻页，放大后自动换成
原图。右边是位置、海拔、朝向（可直接改，改了同时写进照片 EXIF）与说明。

### 去除奥维水印

奥维相机拍的照片左下角压着「经纬度 / 海拔 / 朝向」三行白字。照片 EXIF 里通常有经纬度
与海拔，**唯独没有朝向**——这几行字里最有用的就是它。点「去除奥维水印…」：

1. 用 macOS 自带的文字识别（Vision，经 `ocrmac`）读左下角，先粗读定位，再按原分辨率
   细读水印块；
2. 弹框列出识别结果，朝向可以改。度数与方位字（「东南」）必须落在同一个 45° 扇区，对
   不上就标黄提醒核对；经纬度与照片 GPS 不一致时以照片为准（OCR 会认错个别数字）；
3. 在文字框里取纯白笔画、向外膨胀盖住黑描边作掩膜，交给 LaMa 修补，朝向写进
   `GPSImgDirection`。

修补用 LaMa（Apache-2.0）的 ONNX 版，约 200 MB，不随包分发，第一次用时在照片浏览器里
点「下载 LaMa 模型」（经 hf-mirror 镜像，下载后核对 SHA-256），存到
`<数据目录>/data/models/`。没有模型时退回 OpenCV 的 Telea 算法，能用但岩石纹理会被抹平。
修补只在掩膜附近开 512 像素的窗口按原分辨率做，掩膜以外一个像素都不动。

点位详情里的「去奥维水印」把这个点位的照片一次处理完，没有水印的自动跳过。别的水印、
标签、杂物用「框选修补…」圈出来抹掉。

### 地质水印

「地质水印（镜向、比例尺）…」在照片上加三样东西，都可以拖到想要的位置：

* **镜向罗盘**：指北针按镜向反转画在罗盘里，看照片的人一眼知道北在哪边，下面标
  「镜向 东南 138°」；
* **比例尺**：先「标定」——在照片里的参照物（记号笔约 14 cm、地质锤约 33 cm、一元
  硬币 2.5 cm）上从一端拖到另一端，填它的实际长度；比例尺长度按 1-2-5 自动取一个画出来
  约占照片宽度五分之一的整数，也可以手改，分段可选；
* **信息文字**：默认是点位名、坐标与海拔、拍摄时间，可改。

编辑器里是预览；成品由后端按照片原分辨率重画，另存一版，EXIF 保留，镜向同时写进照片。

### 裁剪、旋转、调色、标注

用开源的 Filerobot Image Editor（MIT）：裁剪、旋转翻转、亮度对比度色温、滤镜、箭头
文字等标注、改尺寸。编辑器的界面翻译自带（不去它的服务器取，离线可用），导出按原图
尺寸。编辑器导出的图没有 EXIF，保存时从当前版本把 GPS、时间、朝向搬过去。

### 光谱

点位只链接光谱库里的条目，不挂光谱文件。野外实测的谱先在「视图 → 光谱库…」里导入
用户光谱库（那里管仪器格式、波长单位与反射率量纲），再回到点位上「链接光谱」——一份谱
只存一处，光谱库里改了名称、分类，点位上看到的就是改过的。光谱库里删了的条目，点位上
标「光谱库里已找不到」而不是悄悄消失。光谱模块不在发行版里时，这一块不出现。

### 依赖

`onnxruntime`（LaMa 推理）、`opencv-python-headless`（兜底修补）、`ocrmac`（macOS 文字
识别）、`piexif`（写 EXIF），前端 `react-filerobot-image-editor`、`react-konva`、`konva`、
`styled-components`。都已写进 `environment.yml` 与 `web/package.json`。OCR 只在 macOS
上可用；在别的系统上去奥维水印的按钮是灰的，其余功能照常。

## 17. 深度学习

提供监督分类与对比学习：从样本库裁剪样本集、训练模型、查看训练曲线与混淆矩阵、整景
预测、分析样本在特征空间中的分布、检索相似区域。命令条上的「深度学习」或菜单栏的同名
菜单打开工作台。工作台浮在画布之上，训练期间可以照常标注和取谱。设计说明与性能测试见
仓库根 `docs/2026-10-13_deep-learning-module-plan.md`。

### 运行环境

训练与预测由仓库根的 `workers/litho_dl` 在所选的 Python 环境中执行，该环境需安装
PyTorch、h5py 与 GDAL。本程序以子进程启动 Worker，自身不导入 PyTorch，安装包也不包含
PyTorch。

工作台「运行环境」页列出本机的 conda 环境。体检会在所选环境中导入一次 PyTorch，并报告
可用的计算设备：Windows 上为 CUDA 显卡，Apple 芯片上为 MPS，其余为 CPU。体检通过后才能
选用。没有合适的环境时，可按 `workers/litho_dl/environment.yml` 新建。

### 任务目录

本程序与 Worker 之间只通过任务目录交换信息。`job.json` 记录任务类型与参数；Worker 运行
时向 `events.ndjson` 追加事件、更新 `status.json`，生成的模型包与栅格也保存在该目录中。
界面只读取任务目录，因此：

* 关闭程序不会中断正在运行的训练，重新打开后任务列表、曲线与结果都会恢复；
* 进程已退出但未完成的任务显示为「已中断」。单击「继续运行」，训练从最近保存的轮次继续，
  预测只计算未完成的分块；
* 用命令行或 VS Code 脚本运行的任务（`workers/litho_dl/scripts/` 下的脚本，参数写在文件
  开头的配置区），只要任务目录位于任务根目录下，同样会出现在任务列表中。

任务根目录默认为数据目录下的 `dl/jobs/`，可在「运行环境」页更改。同一时间只运行
一个任务，其余任务排队。各任务的参数由 Worker 声明，界面据此生成表单，Worker 新增参数或
修改默认值后，表单随之更新。

### 样本集

「样本集」页的「从样本库裁剪」使用第 5 节的裁剪功能，输出格式固定为 h5，裁剪完成后自动
登记。h5 中额外记录每个样本块所属的样本（`sample_keys`），类别表中带有样本库的类别颜色，
模型与分类图沿用这些颜色。

登记时会记录所涉类别的样本状态（各类样本数与样本编号之和）。之后若这些类别的样本有增删
或归属变化，样本集及由其训练的模型将标记为「来源已变化」。仅修改几何而不改变归属的编辑
不会触发该标记。卡片上会提示样本少于 20 个的类别、各类样本数相差悬殊以及缺少测试集等
情况。

### 训练

「训练」页分为「监督分类」与「对比学习预训练」两种。骨干网络以卡片形式列出，标明输入
形式与速度；块大小不满足要求的骨干网络不可选。三维卷积类骨干在 Apple 芯片上无法加速，
在没有 CUDA 显卡的设备上选择时会给出提示。任务开始后，Worker 先用 3 个批次测速，「任务」
页显示预计的每轮耗时与整景预测耗时。

每轮评估前会重新统计 BatchNorm 的均值与方差。样本较少、每轮批次较少时，BatchNorm 的
滑动统计量跟不上权重的变化：在合成数据上，同一份训练集用滑动统计量评估的精度为 0.68，
用批次统计量评估为 1.00。最佳模型默认按验证集宏 F1 选取。验证集按样本整体从训练集中
划出（旧版样本集未记录样本来源时按空间格网划分），避免同一样本的相邻像元同时出现在训练
与验证中。

### 任务监控

「任务」页显示损失、精度与学习率曲线，以及验证集与测试集的混淆矩阵和各类精度。单击混淆
矩阵中的单元格，列出对应的样本块；错分样本按置信度从高到低排列，置信度高的错分更可能是
标注错误。单击某一行在画布上定位，「在画布上选中」与「加入勾选」可将这些样本交给样本树
处理。

### 预测

「预测」页默认使用画布中的当前影像，预测范围可选全图、矢量图层或手绘范围。预测开始后，
画布中出现「实时预测」图层，已完成的分块随即显示；全部完成后，该图层替换为带颜色表与
类别名的分类图，图层编号、顺序与透明度保持不变，同时输出置信度栅格。分类图可直接用作第
7 节「按类别取平均谱」的数据来源。在画布上单击分类图，状态栏显示该处的类别与置信度。
「生成疑难区」将置信度低于阈值的像元合并为面并添加到画布，可在标注模式下据此补充样本，
重新裁剪后再次训练。

实时预测图层读取任务目录中的 `preview.u8`（行×列的 uint8 文件，Worker 每完成一个分块即
写入），不读取 Worker 正在写入的 GeoTIFF。

### 对比学习与特征

对比学习不使用标签，从整景影像（可限定范围）中随机采样，或使用已有样本集，训练骨干网络。
指定带标签的监控样本集后，训练过程中定期用骨干特征做 kNN 分类，并按其精度选出最佳一轮。
结果列在「模型库」的骨干网络中，单击「用于分类训练」即可作为分类训练的预训练骨干，迁移
方式可选冻结骨干、整体微调或骨干小学习率微调（默认），归一化方式沿用预训练时的设置。

「特征」页包括两项功能：

* 样本特征分析：每个样本块显示为一个点（特征的前两个主成分），颜色表示标签。近邻中其他
  类别占比高的样本块列为疑似错标，可在画布上定位、选中或加入勾选。
* 相似区域检索：单击「在画布上选取参考点」后工作台暂时隐藏，在画布上单击添加一个或多个
  参考点（如已知的蚀变带），单击「完成」返回工作台并开始检索。结果为各像元与参考点的特征
  余弦相似度，以色带显示在画布上，单击可查看相似度数值。

骨干网络可以是对比学习的结果，也可以取自任一分类模型。

### 扩展

在数据目录下的 `dl/plugins/` 中放置一个 `.py` 文件，用
`litho_dl.backbones.register_backbone` 声明新的骨干网络，训练页即可选用。加载失败或与已有
骨干网络重名的插件会被跳过，原因显示在「运行环境」页。新的任务类型在
`workers/litho_dl/tasks.py` 中登记参数声明与执行函数。

### 自测

`tests/test_deeplearn.py` 覆盖本程序一侧：任务管理、裁剪与登记、训练、错分样本定位、实时
预测图层、对比学习、特征分析与相似检索；找不到安装了 PyTorch 的 Python 时，只运行不需要
PyTorch 的部分。Worker 一侧在仓库根运行 `python -m pytest tests/workers`，包括骨干网络与
源项目的逐元素对照、分块推理与逐像元推理的逐像元对照，以及中断后继续运行的结果一致性。
