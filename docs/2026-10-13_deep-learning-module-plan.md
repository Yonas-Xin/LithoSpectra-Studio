# 深度学习模块（分类与对比学习）接入方案

本方案在岩谱 LithoSpectra（Web 版）样本库系统中加入监督分类与对比学习预训练。该功能可以脱离样本库单独使用，也可以与样本库、画布、光谱模块联动，支持 macOS 与 Windows。深度学习源项目 `Hyperspectral_Deep-Learning_Private` 仅作参考，不做修改，所有代码位于本仓库。

## 1. 要点

| 事项 | 结论 |
| --- | --- |
| 预测耗时的来源 | 三维卷积模型的耗时主要在前向计算：`Res_3D_18Net` 处理一个 256×256 块需 2300 s（M5，MPS）。一维、二维等快速模型有 20%～40% 的时间花在数据管线上，包括 DataLoader 在进程间传输膨胀 81 倍的 patch，以及在 GPU 上按坐标逐个提取 patch |
| 预测提速方法 | 原始分块只向 GPU 传输一次，在 GPU 上按行切片展开 patch；快速模型使用半精度推理；读取、计算、写入三个阶段由线程衔接。1024×2048 影像实测：二维模型 49.1 s 降至 9.3 s，一维模型 77.6 s 降至 16.9 s |
| 训练提速方法 | 样本集以原始整型一次性载入内存或显存，批次的提取与数据增强都在设备上完成，不启动 DataLoader 子进程 |
| PyTorch 的位置 | 不打入安装包，也不在界面进程中加载。与去噪 Worker 相同，由使用者选择已安装 PyTorch 的 Python 环境，界面以子进程启动 Worker |
| 单独使用与联动 | 以任务目录作为唯一接口。Worker 读取任务目录中的 `job.json`，写出 `events.ndjson` 与结果文件。命令行、VS Code 脚本、界面三种入口生成的任务目录格式相同，界面通过读取任务目录监控进度，因此命令行运行的任务同样可以在界面中查看曲线、加载结果 |
| 模型交付形式 | 模型包，包含 `manifest.json`（网络结构、输入波段与波长、归一化参数、类别表与颜色）和权重文件。预测时 patch 大小从 manifest 读取，不再从文件名推断，也不再反序列化 Python 对象 |
| 平台 | macOS（MPS 或 CPU）与 Windows（CUDA 或 CPU）。不使用多进程 DataLoader 与 `torch.compile`，路径、编码、进程控制在两个平台上一致 |
| 实施顺序 | 先完成 Worker 内核与监督分类全流程（训练、监控、模型库、整景预测），再实现对比学习与特征分析 |

## 2. 源项目审查

### 2.1 性能测试

测试环境：Apple M5（10 核，24 GB 内存），`geo` 环境，PyTorch 2.12.1。输入为 150 波段 int16 数据，patch 大小 9，权重随机初始化（耗时与权重取值无关）。测试文件刚写入磁盘，处于页缓存中。

单个模型的前向吞吐（batch 256，fp32）：

| 模型 | 参数量 | CPU（像元/秒） | MPS（像元/秒） | 256×256 块（MPS） |
| --- | --- | --- | --- | --- |
| Common_1DCNN | 3.1 M | 889 | 27 034 | 2.4 s |
| Common_2DCNN | 3.2 M | 3 255 | 53 925 | 1.2 s |
| HybridSN | 2.6 M | 673 | 1 831 | 36 s |
| SSRN | 0.6 M | 344 | 1 030 | 64 s |
| Common_3DCNN | 4.7 M | 457 | 429 | 153 s |
| Res_3D_18Net | 34.7 M | 57 | 28 | 2338 s |

MPS 没有针对三维卷积优化，`Common_3DCNN` 在 MPS 上比 CPU 还慢，这类模型适合在 CUDA 设备上运行。在 Mac 上实验应以一维、二维模型为主。

半精度（MPS，batch 8192）：`Common_1DCNN` 由 29 350 提高到 77 598 像元/秒，整个模型转为半精度后达到 124 482；`Common_2DCNN` 由 92 981 提高到 228 598，转为半精度后达到 253 268。随机权重下与单精度的分类结果完全一致。batch 小于 2048 时半精度反而更慢，需要配合较大的 batch 使用。

patch 展开（MPS，512×512 块）：按坐标逐个提取为 229 262 块/秒，按行切片（每次 16 行）为 586 954 块/秒，在 CPU 上展开后再上传为 222 348 块/秒。对于二维模型，按坐标提取 patch 的耗时与前向计算相当。

整景预测（1024×2048，含读取影像与写出 uint8 分类结果）：

| 方案 | Common_2DCNN | Common_1DCNN |
| --- | --- | --- |
| 源项目：共享内存 Dataset 与 4 个持久化 worker，fp32，块大小 256 | 49.1 s | — |
| 整块传入 GPU、按坐标提取，fp32，块大小 256 | 36.7 s | 77.6 s |
| 整块传入 GPU、按行切片，fp16，块大小 512，顺序执行 | 9.7 s | 16.7 s |
| 同上，读取、计算、写入三阶段并行 | 9.3 s | 16.9 s |
| 同上，输入为 DEFLATE 压缩 GeoTIFF，顺序执行 | 11.3 s | 20.7 s |
| 同上，输入为 DEFLATE 压缩 GeoTIFF，三阶段并行 | 10.1 s | 18.5 s |

读取一个 512 块，原始 BSQ 或 BIP 文件约 25 ms，DEFLATE 压缩的条带 GeoTIFF 约 224 ms。文件在页缓存中时，读取约占总耗时的一成。输入经过压缩、存放在机械硬盘或网络盘上，或超出页缓存容量时，读取耗时会接近计算耗时；三阶段并行后，读取与计算重叠进行，GPU 只在处理第一块前等待数据（实测 0.9 s）。

环境问题：在 `geo` 环境中先执行 `import torch` 会因 conda 与 PyTorch 各带一份 `libomp` 而崩溃（OMP Error #15）。先导入 numpy 再导入 PyTorch 则正常，无需设置 `KMP_DUPLICATE_LIB_OK`。Worker 入口固定了这一导入顺序。

### 2.2 不再使用共享内存与持久化 worker 的原因

源项目用多个 worker 进程并行执行 Python 层面的逐像元切片。这一步本身每块只需零点几秒，开销大的是切片结果：一个像元的 9×9×150 float32 patch 为 48 KB，一个 512×512 块展开后约 12.7 GB，而原始块只有 79 MB。源方案先在 CPU 上生成膨胀 160 倍的数据，经进程间共享内存交给主进程，再整批传入 GPU。新方案只将原始块传入 GPU，在显存中按行分批展开 patch，用完即释放。

Windows 上的子进程只能以 spawn 方式启动：每个 worker 都要重新导入 PyTorch（耗时数秒），数据集对象需要序列化后传入，共享张量的行为也与 macOS、Linux 不同。持久化 worker 在两个平台上的表现因此不一致，出现的问题往往只能在其中一个平台上复现。

GDAL 读写、NumPy 与 PyTorch 运算都会释放 GIL，读取、计算、写入三个线程可以同时运行，不需要进程间通信，在两个平台上行为一致。

### 2.3 正确性问题

| 位置 | 问题 | 后果 |
| --- | --- | --- |
| `Models/Data.py:110,188,260,318,387,709` | 归一化规则为"最大值大于 100 则乘 1e-4"，训练时按第一个样本判断，预测时按每个块分别判断 | 某个块的值恰好都不超过 100 时，该块输入被放大一万倍，整块结果错误且不报错 |
| `Classifier_Predict.py:319` 与 `:72` | 设备只支持 cuda 与 cpu，指定 `mps` 时 `predict_data.numpy()` 报错 | Mac 上预测只能使用 CPU |
| `Classifier_Predict.py:176-180` | 输出栅格先在内存中创建整幅背景数组再写盘；概率栅格为"类别数×行×列"的 float32 | 20 类、5000×5000 的概率栅格需一次占用 2 GB 内存 |
| `Classifier_Predict.py:228` | 预测时 `init_fig=True`，先读取整景计算背景掩膜，再读取三个波段合成拉伸彩图 | 大影像需额外读取一到两遍全部数据，彩图并未使用 |
| `Classifier_Predict.py:189` | patch 大小从模型文件名中的 `PatchXX` 解析；输入波段数、归一化方式、类别名都不随模型保存 | 文件改名后无法预测；波段数不符时只报形状错误，看不出是影像与模型不匹配 |
| `Classifier_Predict.py:236`、`Frame.py:307-309` | 以 pickle 保存整个模型对象，以 `weights_only=False` 加载 | 依赖源码目录结构，模块路径变动后旧模型无法加载；加载来源不明的文件可执行任意代码 |
| `Models/Models.py:48` | `if skipped == 0` 将集合与整数比较，结果恒为假 | 预训练权重完全匹配时也进入"部分匹配"分支 |
| `Classifier_Train.py:262` | 只要指定了预训练权重就冻结骨干网络 | 对比学习得到的骨干只能做线性探测，不能微调 |
| `Models/Models.py:433`、`:418` | MoCo 队列维度固定为 1024；类中温度默认值为 0.7，配置文件中为 0.07 | 更换投影头维度即报错；不经配置文件调用时温度相差一个数量级 |
| `Frame.py:618` | 对比学习按训练集上前置任务的 Top-1 精度选择最佳模型 | 该指标与下游分类效果无关，选出的不一定是最好的骨干 |
| `Models/Augment.py:109` | 默认进行任意角度旋转（双线性插值） | 插值将相邻像元的光谱混合，生成实际不存在的光谱 |
| `Models/Augment.py:34` | 中心掩膜按第一次调用时的形状缓存 | 改变 patch 大小或波段数后形状不匹配 |
| `Models/Models.py` 中 `Common_1DCNN.forward` | 一维模型接收整个 patch，在前向计算中才取中心像元 | 预测时为每个像元多切出、多传输 80 个不会用到的邻域光谱 |

### 2.4 可以去掉的设计

| 设计 | 处理 |
| --- | --- |
| `ENCODER_REGISTRY` 与 `MODEL_REGISTRY` 两张注册表，加上十几个包装类 | 每个分类模型都是"骨干网络 + 分类头 + 维度适配"的重复代码，改为一张骨干网络注册表，由骨干自行声明输入形式 |
| ETE 模式的第二个编码器 | `encoder_k` 的参数每步直接指向 `encoder_q`（`Models.py:391`），相当于同一网络不计算梯度再运行一遍，多占一份显存。改为单个编码器 |
| DataParallel、`if_full_cpu`、导入时修改 `OMP_NUM_THREADS` | 以单卡使用为主；将线程数设为全部核心再叠加 DataLoader worker，会造成线程争抢 |
| 共享内存预测 Dataset 与多进程 DataLoader | 原因见 2.2 |
| swanlab 与 GradCAM 绑定 | 特征图只在启用 swanlab 时绘制。指标改为本地保存、在界面中绘制曲线后，外部实验记录不再必需 |
| LMDB、HDF5（h5pickle）、DynamicCrop、MIRBS 多套数据集类 | 样本库裁剪已统一输出 h5；无标签采样改用按块读取影像的采样器。`DynamicCropDataset` 在构造时还会修改输入 shp 的字段 |
| 数字编码的配置项 | `data_manage_mode: 1/2`、`train_mode: ETE/MOCO` 等改为有含义的枚举，并由参数声明生成界面 |

### 2.5 保留的部分

- 常用骨干网络的结构定义。原样移植，以便与源实现逐元素对照。
- 分块预测、外部掩膜与跳过背景的整体思路。
- 带热身的学习率调度、按验证集选优、训练结束后在测试集上输出分类报告。
- 光谱掩膜与波段丢弃两种光谱维增强。
- 训练开始前将配置复制到输出目录，便于复现。

## 3. 总体架构

```
样本库系统（界面进程，不含 PyTorch）                       外部 Python 环境（含 PyTorch）
┌──────────────────────────────────────────┐            ┌────────────────────────────┐
│ web/src/deeplearn/   深度学习工作台         │            │ workers/litho_dl/           │
│   环境 · 样本集 · 训练 · 任务 · 模型库 ·     │            │   backbones 骨干网络注册表     │
│   预测 · 特征                              │            │   data      h5 读取与影像采样  │
│        ↑ HTTP 轮询                         │            │   train     监督分类与对比学习 │
│ webapi/dl_routes.py                       │  子进程     │   predict   整景分块推理       │
│ samplelib/modules/deeplearn/              │ ─────────→ │   package   模型包读写         │
│   runtime  环境发现与体检                   │            │   cli       run / doctor / …  │
│   jobs     任务目录、启动、取消、恢复         │ ←───────── │                            │
│   catalog  样本集与模型登记                  │  任务目录   └────────────────────────────┘
│   bridge   样本库、画布与光谱联动             │                       ↑
└──────────────────────────────────────────┘          命令行与 VS Code 脚本（单独使用）
```

### 3.1 代码单元

| 单元 | 位置 | 运行于 | 依赖 |
| --- | --- | --- | --- |
| Worker | `workers/litho_dl/` | 使用者所选的环境 | numpy、PyTorch、h5py、GDAL |
| 平台模块 | `LithoSpectra-Studio/samplelib/modules/deeplearn/` 与 `webapi/dl_routes.py` | 界面进程 | 沿用现有依赖 |
| 界面 | `LithoSpectra-Studio/web/src/deeplearn/` | WebView | 沿用现有前端依赖，不引入图表库 |

Worker 与 `workers/hyde_denoise` 并列，作为普通资源文件随安装包分发，PyInstaller 不对其做依赖分析；`LithoSpectraWeb.spec` 已排除 PyTorch。平台模块按现有模块约定提供 `module.json`，只加入 `full` profile；模块未安装时界面不显示入口。

### 3.2 任务目录

```
<任务根目录>/<job_id>/
├── job.json            任务类型、参数与协议版本，创建后不再修改
├── events.ndjson       事件流，Worker 追加写入，界面按字节偏移增量读取
├── status.json         当前状态（原子替换写入），程序重启后据此恢复任务列表
├── cancel              存在即表示请求取消，与工具箱的取消标志文件做法相同
├── checkpoints/        last.pt 与 best.pt，用于继续训练
├── metrics.json        每轮指标
├── eval/               验证集与测试集的逐样本真值、预测与置信度（.npz）
├── preview.u8          预测时的实时预览栅格（行×列 uint8）
├── blocks.done         各分块的完成标记，继续运行时跳过已完成的分块
├── model/              训练结果：模型包
└── outputs/            预测结果：分类栅格与置信度栅格
```

事件同时写入标准输出与 `events.ndjson`。界面只读取文件，因此程序重启后，或任务由命令行启动时，都可以继续查看进度。

任务状态依次为 `queued`、`running`，最终为 `succeeded`、`failed` 或 `cancelled`。界面启动时若发现状态为 `running` 而进程已不存在，则标记为 `interrupted`：训练任务可从 `last.pt` 继续，预测任务按 `blocks.done` 继续。

任务根目录默认为岩谱数据目录下的 `dl/jobs/`（Windows 打包版为 exe 旁的 `userdata\dl\jobs\`，macOS 打包版为 `~/Documents/LithoSpectra/dl/jobs/`），可以更改。

事件类型包括：`started`、`phase`、`progress`、`estimate`、`epoch`（损失、OA、AA、Kappa、宏 F1、学习率、耗时）、`evaluation`（混淆矩阵与各类指标）、`checkpoint`、`predict_init`（行列数、地理变换、分块网格、类别与颜色）、`block_done`（窗口与有效像元数）、`artifact`、`warning`、`completed`、`failed`。界面忽略未知类型的事件，协议主版本不一致时拒绝运行。

### 3.3 不复用现有 `TaskManager` 的原因

现有长任务的模式是：同一时刻只运行一个任务，显示模态进度框，并在整个任务期间占用样本库锁。这适合耗时几十秒的导入与导出。训练往往持续数小时，需要非模态运行，训练期间仍能标注、取谱和浏览样本库，也不能占用样本库锁。深度学习任务因此由 `deeplearn.jobs` 单独管理：同一时刻只运行一个 GPU 任务，其余排队；读取 h5 统计信息、列出模型等短操作走普通接口。

### 3.4 macOS 与 Windows

| 方面 | 做法 |
| --- | --- |
| 设备 | `auto` 依次尝试 CUDA、MPS、CPU，三者也可单独指定 |
| 半精度 | CUDA 使用自动混合精度与 `cudnn.benchmark`；MPS 将整个模型转为半精度；CPU 保持单精度。每次预测先在第一块上比对半精度与单精度的分类结果，一致率低于 99.9% 时改用单精度并记入日志 |
| 并发 | 只使用线程，不使用多进程 DataLoader 与 `fork` |
| 编译 | 不使用 `torch.compile`（Windows 上依赖不全） |
| 进程 | 启动 Worker 前清理 GDAL、PROJ 相关环境变量，Windows 上不弹出控制台窗口（复用 `toolbox.envs`）。取消时先写入 `cancel` 文件，等待 Worker 在分块或批次之间退出，超时后再强制结束 |
| 文件 | 路径统一用 `pathlib`，JSON 与 NDJSON 统一为 UTF-8。预测先写入 `.partial.tif`，关闭文件后再改名（Windows 上文件未关闭时无法改名） |
| 环境发现 | 复用 `toolbox.envs.discover()`，已覆盖 Windows 上 Miniconda 与 Anaconda 的常见安装位置 |

## 4. Worker 设计

### 4.1 骨干网络注册表

每个骨干网络通过装饰器声明：

```python
@register_backbone(
    "Common_2DCNN",
    input_kind="image",       # spectrum（一维）/ image（二维，波段为通道）/ cube（三维）
    min_patch=1,
    speed="fast",             # fast / medium / slow / very_slow，界面据此提示
)
class Common2DCNN(nn.Module): ...
```

分类模型由骨干网络与分类头组成，对比学习模型由骨干网络与投影头组成，维度适配统一按 `input_kind` 处理。`spectrum` 类骨干只接收中心像元光谱，训练与预测都不使用邻域。

首批移植六个常用骨干网络：`Common_1DCNN`、`Common_2DCNN`、`Common_3DCNN`、`SSRN`、`HybridSN`、`SRACN`。网络结构与源实现一致，以相同权重下输出逐元素一致作为验收标准。

插件目录（岩谱数据目录下的 `dl/plugins/`）中用 `@register_backbone` 注册的骨干网络会被自动发现。Worker 的 `capabilities` 命令以 JSON 输出注册表与各任务的参数声明，界面据此生成选项，不硬编码模型列表。

### 4.2 数据

| 来源 | 用途 | 读取方式 |
| --- | --- | --- |
| 样本库裁剪生成的 `*_dataset.h5` | 监督训练、验证与测试 | 主要来源 |
| 整景影像，可限定范围 | 对比学习的无标签样本 | 按大窗口读取影像，一次切出多个块，缓存为任务目录中的 `unlabeled.h5` |

样本集体积小于可用内存（或显存）的一定比例时一次性载入，以原始整型存放，批次的提取、类型转换与归一化都在设备上完成。150 波段、patch 9、int16 的五万个样本约占 1.2 GB。

样本集超出内存时，由读取线程按 h5 中的连续区段分段读入（每段数千个样本），先打乱区段顺序再打乱段内顺序，经有界队列交给训练循环，不启动子进程。

验证集按样本从训练集中整体划出，比例可调；测试集只在训练结束后使用一次。

### 4.3 归一化

归一化参数在训练开始时根据训练集计算，保存到模型包，预测时使用同一组参数：

| 方式 | 说明 |
| --- | --- |
| `scale`（默认） | 乘以固定系数，如以反射率 ×10000 存储的数据乘 1e-4。系数根据数据类型与取值范围给出建议值，可以修改 |
| `band_standard` | 逐波段减均值、除以标准差 |
| `pixel_l2` | 对每个像元的光谱向量做 L2 归一化 |

### 4.4 数据增强

所有增强按批次在设备上进行，不再依赖 kornia。包括水平与垂直翻转、90° 倍数旋转（无插值）、光谱掩膜、波段丢弃、高斯噪声、整体亮度缩放（模拟光照差异），以及保留中心像元的随机擦除。分类训练默认只启用翻转与旋转，对比学习默认全部启用，强度可调。

### 4.5 训练

监督分类使用交叉熵损失，可选类别加权与标签平滑。每轮计算 OA、AA、Kappa 与宏 F1，默认按验证集宏 F1 选取最佳模型，因为类别不平衡时 OA 会掩盖小类的错误。

对比学习提供批内负样本（源项目的 ETE 模式，改为单编码器）与 MoCo（动量编码器加负样本队列，队列维度随投影头确定）两种方式。指定带标签的样本集时，定期在其上做 kNN 分类并据此选出最佳骨干；未指定时保存最后一轮。

分类训练可以用对比学习得到的骨干网络初始化，迁移方式有三种：冻结骨干（线性探测）、整体微调、骨干以较小学习率微调（默认，学习率比例 0.1）。

CUDA 上默认使用混合精度训练，并进行梯度裁剪。每轮结束保存 `last.pt`，可以中断后继续训练，取消时保存当前一轮。

正式训练前用 3 个批次测速，换算为每轮耗时与整景预测耗时，以 `estimate` 事件报告给界面。

### 4.6 预测

预测分为三个阶段，由两条深度为 2 的有界队列衔接：

```
读取线程                    计算（主线程）                                写入线程
GDAL 读取分块（含边缘）  →   原始块一次性传入设备（int16）             →   按块写入分类栅格与置信度栅格
计算有效掩膜                 转为半精度并归一化                             写入预览文件，记录 blocks.done
                            spectrum：直接取中心像元，不展开 patch            发出 block_done 事件
                            image / cube：按行切片展开 patch，用完即释放
                            前向计算；在设备上求类别与置信度，只回传结果
```

内存占用有上限：队列中最多有三块原始数据；patch 以若干行为单位展开，每批大小由可用显存决定（宽 512、16 行、150 波段、fp16 约 200 MB）。

块大小默认为 512，按可用内存自动调小。每块需多读取 patch−1 行列的边缘，块大小为 512 时额外读取约 3%。

有效像元占多数的块按整行展开，无效像元也参与计算，结果丢弃；有效像元不足一半的块只提取有效像元，避免在大片 NoData 区域上计算。背景按块现场判断（NoData 与外部范围），不再预先扫描整景，也不再合成彩图。

单个分块出错时重试一次，仍失败则停止并报告该块的位置。每完成一块记入 `blocks.done`，中断或取消后再次运行只计算剩余的分块。结果先写入 `.partial.tif`，全部完成后改名。

输出包括：

- 分类栅格：uint8（类别超过 254 个时为 uint16），分块压缩的 GeoTIFF，写入颜色表与类别名（GDAL Category Names），画布可直接按颜色表显示，「按类别取平均谱」可直接识别类别名；
- 置信度栅格（默认输出）：单波段 float32，取最大后验概率或熵；
- 概率栅格（可选）：逐块写入，不在内存中创建整幅数组。

预测前检查：影像波段数须与模型一致；双方都有波长信息时逐波段比对，偏差超过阈值时列出具体波段；影像缺少投影时给出警告。

实时预览：每完成一块，先将类别写入 `preview.u8` 的对应位置，再发出 `block_done` 事件。

### 4.7 模型包

```
<名称>.lithomodel/
├── manifest.json     网络结构、输入形式、patch 大小、波段数、波长、归一化参数、
│                     类别表（标签、名称、代号、样本库类别编号、颜色）、
│                     训练样本集信息、指标摘要、预训练骨干
├── weights.pt        权重字典，以 torch.load(weights_only=True) 读取
├── config.json       完整的训练参数
└── metrics.json      每轮指标与测试集报告
```

对比学习的结果同样是模型包，其 `manifest.json` 中 `task` 为 `backbone`，不含类别表。

### 4.8 命令行

```
python -m litho_dl doctor                      检查运行环境（PyTorch、设备、GDAL、h5py、可写目录）
python -m litho_dl capabilities                输出骨干网络与任务参数的声明（JSON）
python -m litho_dl run <job_dir>               执行任务目录中的 job.json
```

`workers/litho_dl/scripts/` 下另有可在 VS Code 中直接运行的 `train_classifier.py` 与 `predict.py`，参数写在文件开头的配置区。脚本只是生成 `job.json` 再调用 `run`，与界面使用同一套代码。

## 5. 与样本库系统的联动

| 联动 | 做法 |
| --- | --- |
| 样本库到样本集 | 工作台直接调用现有的裁剪功能（勾选的类别、导出层级、按要素划分），裁剪完成即登记。h5 中新增 `sample_keys`，记录每个块所属的样本 |
| 样本集过期提示 | 裁剪时记录样本库路径与所涉类别的样本状态；样本增删或类别归属变化后，样本集及由其训练的模型标记为「来源已变化」，但仍可使用 |
| 类别与颜色 | 类别表从裁剪结果的 `class_table` 传递到模型包与分类栅格，颜色表沿用样本库的类别颜色 |
| 训练监控与画布 | 单击混淆矩阵中的单元格，列出对应的样本块；单击其中一条，画布缩放到该样本；可将这批样本在画布上选中或加入勾选 |
| 画布影像与预测 | 预测默认使用画布中的当前影像，可选用感兴趣区限定范围。预测开始后画布中出现实时预测图层，已完成的分块随即显示，全部完成后替换为正式结果 |
| 预测结果点查 | 在画布上单击分类图，状态栏显示该处的类别与置信度 |
| 低置信度区域 | 置信度栅格按阈值转为「疑难区」图层，可在标注模式下据此补充样本，重新裁剪后再次训练 |
| 预测结果与光谱 | 分类栅格可直接作为「按类别取平均谱」的来源，与样本库中同类别的平均谱对比，检查是否存在系统性误判 |
| 样本特征分析 | 用骨干网络计算样本集中各样本块的特征，以二维散点（PCA）显示，颜色表示类别；单击散点在画布上定位 |
| 疑似错标 | 按"近邻中与自身标签不同的比例"对样本块排序，列出最可疑的样本供核查 |
| 相似区域检索 | 在画布上选取参考点，计算整景各像元与参考点的特征相似度，生成相似度图层（预测流程的变体，只输出单波段） |

## 6. 界面

命令条新增「深度学习」入口，打开浮动工作台，包括七个页面：

| 页面 | 内容 |
| --- | --- |
| 运行环境 | 列出本机的 Python 环境，体检后选用；显示任务根目录、插件目录与 Worker 版本 |

| 训练 | 分监督分类与对比学习预训练两种。骨干网络以卡片列出，标明输入形式与速度；参数提供快速、标准、精细三档预设，其余参数按 Worker 的声明自动生成，高级参数默认折叠。块大小小于骨干要求、波段数与预训练骨干不符等情况在提交前给出说明 |

## 7. 单独使用

三种单独使用的方式都使用同一个 Worker：

1. 命令行或 VS Code 脚本：在脚本开头的配置区填写样本集、骨干网络与输出位置，即可训练与预测，无需打开岩谱。
2. 不打开样本库使用岩谱：在工作台中直接选择 h5 与影像文件，结果为标准的 GeoTIFF 与模型包，可在 QGIS、ArcGIS 中使用。
3. 后续接入：将命令行生成的任务目录放到任务根目录下，岩谱的任务列表即可显示其曲线、混淆矩阵与结果，模型包进入模型库，预测结果可直接加载到画布。

## 8. 扩展

| 扩展 | 方式 |
| --- | --- |
| 新骨干网络 | 在插件目录放置一个 `.py` 文件，用 `@register_backbone` 声明，界面自动列出 |
| 新任务类型（领域自适应、MAE 等） | 在 Worker 中新增任务，提供参数声明与执行函数并在 `tasks.py` 中登记，界面表单由声明生成 |
| 新数据来源 | 在 `data.py` 中实现读取器，返回样本块、标签与元数据 |
| 远程运行 | 将运行环境抽象为本地解释器与 SSH 远程主机两种：远程运行时同步任务目录与数据，经 SSH 启动 Worker，并回传事件与结果。任务目录格式不变，界面无需修改 |

## 9. 分阶段实施

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| 一：Worker 内核 | 骨干网络注册表与六个骨干网络；h5 读取与一次性载入；归一化；数据增强；监督训练；三阶段并行预测；模型包；命令行与 VS Code 脚本 | 移植的骨干网络与源实现在相同权重下输出逐元素一致；合成数据上训练收敛；预测栅格的地理参考、颜色表与类别名正确；分块推理结果与逐像元推理逐像元一致；中断后继续运行的结果与一次运行完成的结果一致；`geo` 环境下全部测试通过 |
| 二：监督分类接入 | 环境体检；任务管理（启动、取消、继续运行、重启后恢复）；样本集与模型登记；工作台各页面；实时预测图层；混淆矩阵定位样本；h5 记录 `sample_keys` | 从样本库裁剪、训练、预测到加载结果全部在界面中完成；重启岩谱后任务列表与曲线恢复；命令行运行的任务可在界面中查看；`tests/run_all.py` 全部通过；编译 app 后实测 |
| 三：对比学习与特征分析 | 无标签采样；批内负样本与 MoCo；按 kNN 精度选优；三种骨干迁移方式；特征页（散点、疑似错标、相似区域） | 用对比学习骨干初始化的分类精度不低于随机初始化；可生成相似度图层；编译 app 后实测 |
| 四：扩展 | 插件目录；低置信度区域补样本 | 按需逐项验收 |

每个阶段的 Worker 测试在 `geo` 环境下用小规模合成数据运行（数秒完成）；平台侧测试以假 Worker 按协议写出事件与结果文件来测试接口，不依赖 PyTorch。每个阶段完成后编译 Web 版 app。

## 10. 范围

- 本机实验以快速模型为主，暂不实现远程运行。
- 不兼容源项目的旧模型（`*_best.pt`）与旧数据集格式（`.meta.json`、`datasets.txt`、bin、tif）。
- 首批移植六个骨干网络：`Common_1DCNN`、`Common_2DCNN`、`Common_3DCNN`、`SSRN`、`HybridSN`、`SRACN`，其余可通过插件目录添加。
- `deeplearn` 模块只加入全功能版。
